# INGEST-MOMENT-ZONE-FIX — деплой (2026-08-09)

**Задача:** `INGEST-MOMENT-ZONE-FIX-DEPLOY` (класс B, мандат `ADR-147` выдан поимённо
`2026-08-09`, чат). Оба объекта деплойного объёма развёрнуты и функционально проверены.
Процедура — `05_CONVENTIONS §Процедура деплоя … вариант Б`
(`reference/deploy_procedure_2026-08-03.md`).

## Итог одной фразой

Два места исправлены: `cf-facts` (возвраты и закупки — дата документа теперь считается по
Asia/Bishkek, `+6ч` от UTC, а не срезом первых 10 символов строки) и `transferConfig`
`sq_marts_expenses` (списания/комиссии — та же замена в SQL). Проверка на документе №00008 и
переход через полночь подтверждены синтетически ещё на подготовке
(`reference/ingest_moment_zone_fix_2026-08-08.md`); на живых данных мая-2026 сдвига не
обнаружено ни по одной из трёх сверенных пар — все три остались сошедшимися с эталоном.

## Объект A — `cf-facts`

- Ревизия: `cf-facts-00010-mog` → `cf-facts-00011-mab`.
- Код-репо: ветка `deploy/cf-facts-2026-08-09-moment-zone` (коммит `239e571`) → слита в `master`
  (коммит `508ca64`), запушена.
- Read-back: sha256 архива побайтово совпал с веткой, мусора нет.
- Функциональная проверка: `mode=returns` (window_days=100, окно `2026-05-01…2026-08-09`) —
  `104` строки; `mode=purchases` (полный рефреш) — `4 424` строки. Оба режима подтверждены
  read-only по `_loaded_at` целевых таблиц (клиентский `gcloud` таймаутился на `purchases`,
  слепой retry не делался).
- Полный разбор, sha256, чек-лист процедуры — `reference/code/cf-facts/MANIFEST.md`
  §«Деплой `cf-facts` — дата документа по Asia/Bishkek…».

## Объект B — `transferConfig sq_marts_expenses`

- `transferConfig` `6a22a243-0000-20fd-a458-883d24f4cad4`: `CAST(l.moment AS DATE)` /
  `CAST(c.moment AS DATE)` → `DATE(…, 'Asia/Bishkek')`, обе строки. Read-back побайтово совпал
  с целевым текстом (`updateTime: 2026-08-09T13:27:47Z`).
- Функциональная проверка: ручной прогон (`bq mk --transfer_run`, `run_id`
  `.../runs/6a78234d-0000-297e-a336-582429c36118`) — `state=SUCCEEDED`, без ошибок. Математически
  идентичен завтрашнему штатному прогону (`11:10 UTC`) — тот же детерминированный запрос,
  `WRITE_TRUNCATE`.

Ни по одной из двух проверенных пар сдвига нет: ни один документ мая-2026 не попал в полосу
`UTC [18:00;24:00)` на границе месяца — сдвиг формулы затрагивает только документы этой полосы,
и в мае-2026 таких, по факту данных, не оказалось. Сдвиг реален в других месяцах (например, июль
2026 несёт `14` документов `commission` и `7` документов `loss` в этой полосе, `Условие 1`
мандата, `step2_run.log`), но месячные суммы не изменились и там — ни один из этих документов не
пришёлся на последний день месяца.
