## §3 Что установлено

1. **`attemptDeadline = 1800s`** — значение, предписанное `ADR-023 §5/§6`, стоит в конфиге на `2026-07-26T14:46:56Z`. Подтверждает применение правки (было `180s`).
2. **Серверный `--timeout` самой Cloud Function = `1800s`** (`11_INFRA_FACTS §CF`) ⇒ значения совпадают, ложный клиентский `504` исключён по построению (`ADR-023 §5`). Соответствует закрытому `Q-43`.
3. **Последний прогон: `2026-07-25T21:00:00.786625Z`**, что соответствует слоту `0 3 * * *` в `Asia/Bishkek` (03:00 локального 2026-07-26 = 21:00Z предыдущих суток).
4. **`status: {}` — пусто, то есть прогон завершился без ошибки.** Прежний `status.code = 4` (прогон 2026-07-24, до правки), зафиксированный в `ADR-048 §Контекст` как остаток, **в конфиге больше не присутствует**.
5. **`retryConfig` без изменений:** `maxRetryDuration = 0s` ⇒ ретраев нет; падение Scheduler тихо проглатывается, алерт только от мониторинга `5xx` на Cloud Run (соответствует `11 §CF`, DROP-DUP с `RB-42`).
6. **`state: ENABLED`**, расписание и таймзона не изменились.

## §4 Что НЕ установлено (оговорки, `ADR-021 §2`)

1. **Точное время правки `attemptDeadline` в репо не зафиксировано** — `11_INFRA_FACTS §CF` стр.25 указывает только локальную дату (`2026-07-26`), без метки времени. Прогон `2026-07-25T21:00:00Z` (= локальное 2026-07-26 03:00) **позже** документированного UTC-якоря сессии, в которой правка применялась (`2026-07-25T19:44:52Z`, `11 §CF` стр.27 / `Q-63`), поэтому прогон **с высокой вероятностью** шёл уже с `1800s`. Строгого доказательства этого в снимке нет: `describe` показывает текущий конфиг, не конфиг на момент прогона.
   ⇒ **`ADR-048 §1` считается подтверждённым по эффекту с этой оговоркой.** Однозначное подтверждение даст следующий прогон (`2026-07-26T21:00Z` либо позднее), у которого `lastAttemptTime` окажется строго позже даты правки.
2. **OIDC этим снимком не переверифицирован** — поле `httpTarget` в фильтр формата не запрашивалось. Последнее подтверждение `--oidc-service-account-email=etl-sa@msklad-bi-prod.iam.gserviceaccount.com` — `11 §CF` стр.25 (2026-07-26, сохранён при partial-update). Настоящий файл этого факта не обновляет и не опровергает.
3. **Предыдущий read-back (заявленный в `11 §CF` стр.25 как выполненный) не восстановлен.** Настоящий файл фиксирует состояние **на 2026-07-26T14:46:56Z** — это фикс-форвард провенанса, а не ретроактивная валидация прошлого замера (`ADR-052 §9`).

## §5 Достоверность лога
