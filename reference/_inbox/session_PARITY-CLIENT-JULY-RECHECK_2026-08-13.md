## NEW_DECISIONS

- ADR-0XX: Атрибуция менеджера в `marts.sales_overview` переводится на владельца документа с
  границей `2026-05-01`; простая замена отклонена замером; мандат класса B выдан поимённо
  Контекст: клиент предъявил расхождение разреза по менеджеру за июль (`77 006 819,86` против
  `74 745 820,29`). Механизм — витрина режет по менеджеру контрагента, отчёт МойСклада по
  владельцу документа; поле `document_owner_employee_id` живёт в ядре с `2026-08-08`, в витрине
  отсутствует.
  Решение: §1 механизм подтверждён арифметически (`74 745 820,28` против эталона `74 745 820,29`,
  копейка округления). §2 простая замена поля ОТКЛОНЕНА замером: до `2026-05-01` поле заполнено
  на `4 575 688,59` из `352 853 922,06` KGS, то есть `98,7 %` ранней истории потеряло бы разрез;
  досев невозможен — окно `90` суток. §3 принят вариант (3): до `2026-05-01` атрибуция прежняя,
  с `2026-05-01` владелец документа, пустое → `'Не указан'`; дата стыка не выдумана под задачу,
  это финишная черта `ADR-069`. §4 форма правки предписана дословно (четыре места, локализация
  подтверждена грепом), включая три запрета: `COALESCE` только в новой ветке, разные алиасы у двух
  соединений со справочником сотрудников, ничего кроме четырёх мест. §5 приёмка — четыре проверки
  с зафиксированными числами. §6 откат односоставный: возврат прежнего текста запроса; снимок
  таблицы НЕ требуется, потому что витрина строится `CREATE OR REPLACE` из ядра — свойство
  единичное и на другие деплои не переносится. §7 пять принятых следствий объявляются клиенту ДО
  правки. §8 пара реестра паритета «Продажи» не затрагивается — меняется разрез, не суммы.
  Последствия:

    §Открытые вопросы и §Мандат Claude Code — коммит `544280c`.
  - [без правок] `reference/sql/sq_marts_sales_overview.sql` — снапшот правит сессия-исполнитель.
