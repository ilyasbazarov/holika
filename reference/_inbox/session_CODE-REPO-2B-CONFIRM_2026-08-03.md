## NEW_DECISIONS

- ADR-0XX: Строка реестра, чьё действие за владельцем, обязана нести способ проверки СОСТОЯНИЯ;
  «действие владельца» и «состояние непроверяемо инструментом» разделяются
  Контекст: шаг 2b `CODE-REPO-STANDUP` был исполнен владельцем `2026-08-01T16:35:55Z` и оставался
  незафиксированным до `2026-08-03`, потому что формулировка «исполняет владелец, инструменту не
  отдаётся» читалась сессиями как «состояние проверке недоступно». Проверка стоила одного
  read-only вызова внутри класса A. `ADR-109 §5` объявил этот гейт единственным гейтом всего
  деплойного потока — то есть цена ошибки чтения равнялась простою всей очереди правок.
  Решение: (§1) в реестре разделяются два свойства строки — КТО исполняет действие и КАК
  проверяется состояние; (§2) строка, чьё действие за владельцем, обязана нести способ проверки
  состояния: конкретный read-only вызов либо явное «проверке инструментом не поддаётся» с
  причиной; (§3) сессия, стартующая с задачи, чей гейт есть действие владельца, обязана СНАЧАЛА
  выполнить названную проверку и только потом считать задачу заблокированной — «гейт объявлен» не
  есть «гейт стоит»; (§4) правило применяется ретроспективно к строкам с тем же признаком, найденным
  сплошным поиском (`ADR-083 §2`), с решением по каждому совпадению.
