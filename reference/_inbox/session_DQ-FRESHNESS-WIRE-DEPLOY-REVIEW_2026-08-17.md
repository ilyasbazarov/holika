## NEW_DECISIONS  (→ append в 06_DECISIONS_LOG.md как ADR; "нет" если нет)

- ADR-0XX: Готовность `DQ-FRESHNESS-WIRE, деплой` — НЕ ГОТОВ: шесть из двенадцати подключённых
  проверок свежести могут заблокировать конвейер; наблюдающая форма требует двух условий;
  приёмка деплоя обязана предъявлять состав живого механизма

  Контекст. Владелец запросил мандат класса B на выезд `cf-dq` при отсутствии критических
  возражений архитектора. Ревью проведено по коду построчно, а не по образцу.

  Решение.
  (§1) **Вердикт НЕ ГОТОВ.** Шесть `check_freshness_*_business` не несут `try/except`, тогда как
  шесть парных `*_technical` несут (программный обход всех двенадцати функций). Цепочка отказа
  замкнута: `run_row` (`helpers.py:18`) исключения не глотает → `main()` ловит и ставит
  `passed=False` → `all_passed=False` → `DQ Gate FAILED` → `step_promote` не исполняется.
  (§2) **Наблюдающая форма определяется ДВУМЯ условиями:** возврат `True` на всех путях И
  перехват всего внутри функции. Второе условие ранее нигде не было записано, из-за чего форма
  применена наполовину при полном соблюдении первого.
  (§3) **Риск не гипотетический:** три триггера — транзиентная ошибка BigQuery (`144`
  дополнительных запроса в сутки), изменение схемы или имени наблюдаемой таблицы (то самое
  событие, ради которого проверки подключаются), сдвиг прав `cf-dq`. Выкладка как есть делает
  ровно то, против чего написан сам патч (комментарий над блоком проверок в `main.py`), и
  повторяет класс, за который проект платил дважды (`ADR-122`/`ADR-153`, `ADR-152`).
  (§4) **Форма фикса назначена, вариантов нет:** перенести существующую форму с шести
  `*_technical` на шесть `*_business`, тело целиком в `try`,
  `except Exception as e: return True, f"EXCEPTION (notify-only, не блокирует): {e}"`. Шесть
  блокирующих проверок, `check_drift_zero_docs` и `main()` не трогать — внешний `except` в
  `main()` корректен и есть последняя линия для блокирующих проверок.
  (§5) **Утверждение `dq_gate_block_bounded_2026-08-17.md §1` о тринадцати неблокирующих
  проверках признано неверным для шести из тринадцати** (класс `ADR-021 §2`/`ADR-044`: вывод по
  образцу вместо построчной проверки). Операционная процедура `DQ-GATE-BLOCK-BOUNDED` в силе:
  список блокирующих проверок пополняется шестью именами, диагностический запрос, порог `24`
  часа и процедура ручного снятия не меняются.
  (§6) **Приёмка деплоя обязана предъявлять СОСТАВ живого механизма** — список имён проверок из
  `audit.dq_runs` первого естественного прогона (`19` пар, двенадцать `freshness_*` поимённо), а
  не только `sha256` архива. Основание — `Q-111`: приёмка прошлого выезда `DQ-CFDQ-DEPLOY`
  прошла полностью и объекта не достигла. Дополнительно: все шесть блокирующих проверок в том же
  прогоне `passed=true`; любое `passed=false` у `freshness_*` есть немедленный откат.
  (§7) **Остальная готовность чиста:** дрейфа снапшота от `cf-dq-00009-coy` нет (ровно один
  коммит `c9905a3`, ровно один файл `main.py` — класс `ADR-152`/`ADR-173` исключён замером);
  откат — трафик на `cf-dq-00009-coy` без пересборки; гейт `ADR-065` снят (`ADR-115 §1`).
  (§8) **Мандат класса B архитектором не выдаётся ни при каком вердикте** (`ADR-076 §2`, форма
  `ADR-146 §1`/`§2-§6`, `ADR-159`, `ADR-163`, `ADR-173 §5`). Настоящее решение готовит объект,
  откат, приёмку и вердикт; выдача — владельца.

## NEW_CONVENTIONS  (→ предложение правки 05; "нет" если нет)

- proposed: **Проверка, объявленная неблокирующей, обязана удовлетворять двум условиям сразу:
  возвращать «прошло» на всех путях И перехватывать все исключения внутри себя.** Достаточно
  нарушить второе — и вызывающий слой, оборачивающий вызов собственным `except`, превратит
  наблюдение в блокировку. Проверка соблюдения выполняется построчным обходом КАЖДОЙ функции,
  не выводом «написаны по образцу». Мотив: шесть из двенадцати проверок свежести `cf-dq`
  прошли ревью подготовки и попали в утверждение «структурно не могут вернуть False», не имея
  `try/except` вовсе. Не применять без апрува владельца.
