## NEW_DECISIONS  (→ append в 06_DECISIONS_LOG.md как ADR)

- ADR-0YY: Очередь до передачи клиенту зафиксирована артефактом: `26` задач в пяти уровнях по
  критерию отсечения `ADR-140 §4`, `9` из них блокируют передачу; назван единственный жёсткий срок
  очереди (`2026-09-29`); заводится `INFRA-FACTS-LANDING`

  **Контекст.** `ADR-140` объявил финиш Epic-1 (реестр паритета `7/7`, дата `2026-08-07`), ввёл
  ВТОРОЙ критерий «регламент пересъёма работает» (`§3`) и фазу передачи клиенту с критерием
  отсечения задач (`§4`). Сам критерий был введён, но НИ ОДНА открытая строка реестра по нему не
  квалифицирована — то есть инструмент отсечения существовал, а результат его применения нигде не
  записан. Владелец запросил счёт: сколько задач отделяет проект от передачи клиенту без
  техдолга, который вернёт клиента через недели.

  **Решение.**

  §1 **Очередь фиксируется артефактом `reference/handover_queue_2026-08-08.md`, а не текстом
  решения.** Список из `26` задач с ID для тегирования, наличием брифа, гейтами и однострочной
  сутью каждой живёт в `/reference` по общему правилу («полный ход — в артефакт, в `07_STATE` —
  следствие плюс ссылка», `ADR-105 §1`). Основание отдельного артефакта, а не абзаца деталей:
  список длиннее любого разумного абзаца, обязан читаться целиком перед планированием и
  переживает несколько сборок без переписывания. accepted (архитектор).

  §2 **Каждая открытая строка реестра квалифицирована по `ADR-140 §4`; результат — пять уровней.**
  Уровень 1 (`9` задач) — неверное число на клиентской поверхности либо тихий отказ: блокирует
  передачу. Уровень 2 (`3`) — второй критерий финиша `ADR-140 §3`. Уровень 3 (`3`) — июльский
  хвост. Уровень 4 (`8`) — тихие мины и гигиена данных. Уровень 5 (`3`) — документы передачи.
  Итого `26`. Вне передачи — ≈`30` строк, по каждой корзине названа причина невыполнения критерия.
  Статусы, гейты и классы взяты из реестра дословно: настоящий ADR НЕ переоценивает ни одной
  строки, он их СОРТИРУЕТ. accepted (архитектор).

  §3 **Назван единственный жёсткий срок очереди: `2026-09-29`.** `WEEKLY_WINDOW_DAYS = 90`
  (`reference/code/cf-facts/config.py`) выпускает июль-2026 из окна пересборки; после этой даты
  правка, обязанная изменить ИЮЛЬСКИЕ числа задним числом, штатным путём не применима. Факт был
  записан при одной строке (`SALES-INGEST-PATCH-DEPLOY`, `07_ARCHIVE.md:204`), а касается двух —
  `SALES-DOCUMENT-OWNER-DEPLOY` и будущего фикса `INGEST-DEMAND-APPLICABLE-FILTER`. Поднят на
  уровень очереди, чтобы не был потерян вместе с архивированной строкой. accepted (архитектор).

  §4 **Заводится `INFRA-FACTS-LANDING`, сводящая `Q-11`/`Q-12`/`Q-13`.** Критерий `ADR-140 §4`
  выполнен по пункту (iii): три узла живой инфраструктуры (бизнес-метрики, служба алертов, состав
  недельного прогона) не описаны в живых доках, притом что факты под них добыты
  (`reference/infra_facts_sweep_2026-08-01.md`) и лежат неперенесёнными с `2026-08-01` — причина
  названа там же: та сессия была класса A и писала только в `/reference`. Три отдельных захода за
  одним и тем же артефактом есть трижды оплаченный вход в контекст. accepted (архитектор).

  §5 **Три строки объявлены подлежащими переквалификации, а не исполнению:**
  `SALES-CONSIGNMENT-REVENUE`, `SALES-PERIMETER-EXTEND`, `Q-78`. Их гейты сняты фактом проходом
  `2026-08-08`, но статусы тем проходом намеренно не переоценивались

  до проверки — значит считать сделанное несделанным. accepted (архитектор).
