## ADR-0XX · Форма фазы 2 изоляции сессий: дерево заводится явной git-командой с точкой ветвления HEAD; требование настройки `worktree.baseRef` снимается; приёмка на уровне git исполнена контр-прогоном

**Дата:** 2026-07-29 · **Статус:** §1-§8 accepted (владелец, сессия CC-SESSION-ISOLATION-P2, выбор варианта (Б) из трёх)
**Контекст:** `ADR-080 §5` назначил фазой 2 отдельное рабочее дерево на сессию и потребовал установки `worktree.baseRef: "head"`. Разведка среды показала: настройка не задана нигде (проектный `.claude/settings.json` несёт только раздел прав, пользовательский `~/.claude/settings.json` — только тему), то есть действовало значение по умолчанию, то самое, которое `ADR-080 §5(iii)` называет ловушкой. Подкоманды `config` у инструмента нет (раздел `Commands` справки прочитан целиком), задать ключ можно только файлом настроек или через интерфейс приложения. Владелец запускает сессии из десктопного приложения.

**Решение:**

§1 **Форма фазы 2 назначается: дерево заводится явной командой git, не флагом инструмента.**
```
git worktree add .claude/worktrees/<TASK> -b s/<TASK> HEAD
```
Точка ветвления задана аргументом `HEAD` и умолчаний не оставляет. **`ADR-080 §5(iii)` superseded-in-part:** установка `worktree.baseRef: "head"` перестаёт быть обязательной, потому что вопрос, который она решала, при этой форме не возникает. Основания два. Первое: настройка, живущая только в файле настроек машины владельца, не переживает переклонирование и частью метода не является — тот же дефект, что был у исключения через `.git/info/exclude` (`ADR-080 §5(iv)`). Второе: документация инструмента прямо указывает git как путь для полного контроля над расположением дерева и выбором ветки; документация фактом не является (`ADR-021 §2`) и приводится как основание выбора, не как доказательство. accepted (владелец).

§2 **Размещение: `.claude/worktrees/<TASK>`.** Путь внесён в `.gitignore` коммитом `aa8fae6` (`ADR-080 §5(iv)`), совпадает с местом по умолчанию у инструмента, и замер подтвердил: при двух вложенных деревьях `git status` основного дерева пуст. Размещение вне репо отклонено: засоряет родительский каталог и требует помнить пути. accepted.

§3 **Приёмка на уровне git ИСПОЛНЕНА контр-прогоном** (`2026-07-28T20:34:54Z`, лог `/tmp/wt_accept.log`, в репо не вносится как разовый диагностический). Три факта: (i) два дерева заведены от `3baa491`, каждое на своей ветке, `git worktree list` показывает три записи; (ii) **изоляция индексов подтверждена** — `git add reference/_inbox/_probe_A.md` в дереве A дал строку в статусе A и ПУСТОЙ статус в дереве B и в основном дереве, то есть условие приёмки `ADR-080 §5` выполнено дословно; (iii) хук из связанного дерева срабатывает — заведомо провальный коммит вернул `PRE-COMMIT FAIL: 07_STATE.md правится без обновления updated_at` и RC 1, что независимо переподтверждает `ADR-080 §5(i)`. Уборка `git worktree remove --force` прошла без следов. accepted.

§4 **Что замером НЕ подтверждено, названо явно (`ADR-021 §2`).** Расхождение локального `main` и `origin/main` в прогоне снова равнялось нулю, как и в замере `ADR-080 §5(iii)`: ловушка ветвления не воспроизведена ни разу. Под формой §1 она невоспроизводима по построению, потому что точка ветвления есть аргумент команды, а не значение настройки. Это названо, а не выдано за доказательство корректности. accepted.

§5 **Остаток приёмки, скриптом не проверяемый.** Контр-прогон проверял git, не приложение. Открыто: откроется ли `.claude/worktrees/<TASK>` в десктопном приложении как обычный проект и останется ли сессия работать в ней. Закрывается первым реальным прогоном задачи в дереве. **До этого прогона параллельный запуск остаётся закрытым.** Отдельный `Q` не заводится: остаток принадлежит задача-строке `CC-SESSION-ISOLATION`. accepted.

§6 **Порядок сессии в дереве.** Старт: `git worktree add .claude/worktrees/<TASK> -b s/<TASK> HEAD`, открыть эту папку в приложении как проект, дальше обычный старт по `CLAUDE.md`. Конец: коммит своих артефактов поимённо в свою ветку, session-блок одним новым файлом в `reference/_inbox/` (`ADR-080 §4`), дерево остаётся до сборки. Проверка на старте `git worktree list` показывает забытые деревья прошлых сессий. accepted.

§7 **Слияние веток и уборка деревьев отдаются проходу сборки** (`_ASSEMBLER.md`). Сборка идёт в основном дереве, сливает ветки `s/<TASK>` в `main`, затем разбирает буфер и удаляет отработавшие деревья и ветки. Конфликтов при слиянии не ожидается по построению фазы 1: ветки не трогают `07_STATE`, `06_DECISIONS_LOG` и `06_INDEX`. Конфликт, если он всё же возникнет, есть громкий отказ и обрабатывается как конфликт блоков (`_ASSEMBLER.md §6`, остановка и вопрос). accepted.

§8 **Правки правил вне scope буфера, названо во избежание тихого расхождения.** Буфер и сборка покрывают только `07_STATE`, `06_DECISIONS_LOG`, `06_INDEX`, `07_ARCHIVE` (`ADR-080 §4(i)/(iv)`). Правки `CLAUDE.md`, `05_CONVENTIONS.md` и файлов ролей под сборку не попадают и коммитятся сессией самостоятельно, поимённо, как её артефакты (`ADR-080 §4(iii)`). При параллели в разных деревьях две правки одного файла правил дадут мердж-конфликт при сборке, то есть громкий отказ, а не тихое смешение. Отдельного механизма под это не вводится: случай редкий, а лекарство было бы дороже болезни. accepted.
