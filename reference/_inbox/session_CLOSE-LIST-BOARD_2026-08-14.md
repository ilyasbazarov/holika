## NEW_DECISIONS  (→ append в 06_DECISIONS_LOG.md как ADR; "нет" если нет)

- ADR-0XX: Пусковой список сессий выводится из статусов строк реестра, а не из пункта
  «Следующий шаг» стенд-апа; три сессии 2026-08-14 признаны правыми, дефект лежит в списке

  Контекст. `2026-08-14` владелец запустил три сессии класса A по пункту «Следующий шаг»
  стенд-апа `07_STATE.md:23`. Все три отчитались «работы нет». Проверка репозиторием
  подтвердила все три отчёта: класс-A часть `MARTS-BUILD-STAMP-PREP` лежит в `main`
  коммитом `cc37bff`, класс-A часть `DQ-FRESHNESS-WIRE` — коммитом `c9905a3` (`CHECKS`
  `7`→`19` пар), у `PARITY-CLIENT-JULY-RECHECK` остаток по `07_STATE.md:1898` лежит на
  архитекторе и владельце. Обе первые части приземлила ТА ЖЕ сборка буфера 2026-08-13,
  что записала стенд-ап. То есть файл противоречил сам себе: пункт `23` называл работой
  то, что строки `1894` и `1897` того же файла уже отмечали сделанным.

  Решение.
  (§1) Три отчёта признаны верными. Требовать от исполнителя повторить уже приземлённую
  работу означало бы записать выдуманный факт поверх принятого — прямое нарушение
  anti-improvisation (`_METHOD §6`). Исполнители остановились ровно там, где метод велит.
  (§2) Механизм протухания назван: пункт «Следующий шаг» — единственная из пяти строк
  стенд-апа, говорящая о будущем, и он берётся из ПОСЛЕДНЕГО блока прохода (`ADR-084 §3`),
  автор которого не видел соседних блоков того же буфера. Дефект структурный, не
  исполнительский: ни одно правило не обязывает сборщика пересчитать этот пункт против
  фактически применённых блоков.
  (§3) Пусковой список задач читается из `07_STATE §Открытые вопросы` (статус строки) и
  `§Мандат Claude Code` (класс, мандат, гейт), а стенд-ап остаётся навигацией для человека.
  При расхождении между стенд-апом и строкой выигрывает строка.
  (§4) Правка `_ASSEMBLER.md` (обязанность сборщика пересчитать пункт «Следующий шаг»
  против применённых блоков) не назначается этим решением: она есть работа о методе, а
  фаза передачи по `ADR-156 §2` отправляет находки текстом в ограничения, не в задачи.
  Владелец может назначить её отдельно, вытеснив строку списка по бюджету `ADR-156 §3`.

  Последствия.

    фактически исполнимым задачам).
  - [сейчас] `07_STATE.md §Подробности для модели` — три абзаца выше.
  - [без правок] `06_DECISIONS_LOG.md` `ADR-084` — не пересматривается: правило замены
    стенд-апа верно, недостаёт пересчёта одного пункта.
  - [без правок] `_ASSEMBLER.md` — см. §4, работа не назначается.
  - [без правок] `reference/scope_close_freeze_2026-08-10.md` — потолок `9` не двигается.
