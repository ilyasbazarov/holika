## NEW_DECISIONS

- ADR-0XX: Форма отметки времени сборки витрин — вариант «две колонки»; вариант «одна производная
  колонка» отклонён как замирающий вместе с витриной; развилка агрегации закрыта `LEAST()`
  Контекст: строка `MARTS-BUILD-STAMP` (строка `7` блока B списка закрытия) стояла на предметном
  гейте «выбор варианта — owner-gated»; сессия 2026-08-10 подготовила по два независимых варианта
  на каждую из трёх разобранных таблиц и намеренно не ранжировала их.
  Решение: §1 принимается вариант «две колонки» (`_marts_built_at TIMESTAMP` = `CURRENT_TIMESTAMP()`,
  `_source_max_loaded_at TIMESTAMP` = `MAX(_loaded_at)` источника) для `marts.customer_invoices_ar`,
  `marts.expenses`, `marts.weight_flow`. §2 вариант «одна производная колонка» отклоняется: величина
  вычисляется в момент сборки и при остановке сборки замирает на последнем малом значении, предъявляя
  ложный сигнал свежести — то есть усиливает ту самую маскировку, ради устранения которой строка
  заведена; момент пересборки из него не восстановим, чем нарушается критерий приёмки
  `briefs/MARTS-BUILD-STAMP.md` («каждый вариант несёт И отметку момента пересборки, И сигнал возраста
  источника»). §3 при нескольких источниках берётся `LEAST()` по `MAX(_loaded_at)` — вопрос «какой
  источник встал» адресован слою ядра, не витрине; названа оговорка о `core.fact_loss` и
  `core.fact_sales_profit`, у которых собственной проверки свежести нет. §4 применение гейтится
  проверкой потребителей Looker Studio класса A; два из трёх Custom Query замерены и безопасны,
  `marts.weight_flow` читается страницей напрямую и не проверен. §5 применение затрагивает три живые
  конфигурации Data Transfer Service — пакетный мандат запрещён (`ADR-115 §5`). §6 `core.dim_fx_rates`
  и `marts.expenses_staging` остаются в реестре известных ограничений (`ADR-156 §5`), в работу не
  возвращаются.

- ADR-0XX: Строка `2` списка закрытия исполнена наполовину — проверки свежести шести таблиц ядра

  становится `8` из `9`; правило `ADR-156 §3` («список не растёт») не нарушается — новая строка не
  заводится, доисполняется существующая. §4 доисполнение оформляется задачей `DQ-FRESHNESS-WIRE`
