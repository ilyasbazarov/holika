## NEW_DECISIONS

- ADR-0XX: Проверка параллельности получает второй источник набора файлов — поле `Пишет:` таблицы мандата; класс B запрещается механически; `ADR-090 §3` superseded-in-part в части носителя объявления

  Контекст: `ADR-082 §1` требует прогона `tools/parallel_check.sh` перед одновременным запуском двух задач, а `ADR-086 §1` разрешает исполнять задачу без брифа. Скрипт читал набор файлов только из `briefs/<TASK>.md`, поэтому для задач без брифа возвращал `RC 3` и правило параллельности оставалось без исполняющего механизма для целого класса сессий (`SALES-ORPHAN-CONFIRM`, `STATE-COMPACT`, `UNGATED-QUEUE-ADJ`). Дефект найден проверками после сборки 2026-08-02 и подтверждён прогоном на живой задаче. Полный разбор — `reference/parallel_check_no_brief_2026-08-02.md`.

  Решение:

  §1 **Носитель объявления для задач без брифа — таблица `07_STATE §Мандат Claude Code`, поле `Пишет:`.** `ADR-090 §3` называл носителем «текст запуска», и это `superseded-in-part`: текст запуска не является файлом репо, машинно непроверяем и до старта сессии нигде не сохраняется. Рекомендация сессии `UNGATED-QUEUE-ADJ` («читать набор из session-блока») отклонена по механизму: блок пишется в конце сессии, а проверка нужна до её запуска. Таблица мандата этим требованиям удовлетворяет: она лежит в репо, заполняется по действующему правилу и её парность со строкой реестра уже обязательна (`ADR-090 §1`). accepted (архитектор).

  §2 **Приоритет источников: бриф, затем таблица.** Бриф задача-специфичен и точнее; таблица — запасной носитель. Источник печатается в выводе по каждой задаче, иначе вердикт непроверяем (`ADR-044`). Читаются ВСЕ строки задачи, включая шаговые (`<TASK>, шаг 2a`): набор задачи есть объединение наборов её шагов. accepted (архитектор).

  §3 **Класс задачи запрещает параллель механически.** Задача, все строки которой класса B, даёт `RC 1` — прежний вердикт скрипта отсылал к ручной проверке «отдельно по `07_STATE`», то есть правило `ADR-082 §1` держалось на памяти исполнителя. Смешанный класс (`A/B`) печатает предупреждение и разбирается по файлам: запуск может касаться шага класса A, и отказ по всей задаче был бы неверен. Класс, который установить не удалось, печатается как неустановленный и на вердикт НЕ влияет — отсутствие данных фактом не является (`ADR-021 §2`). accepted (архитектор).

  §4 **Подавлены два источника ложных пересечений.** Плейсхолдер `<TASK>` раскрывается в имя задачи, иначе любые две задачи ложно пересекались бы на общем шаблоне `reference/_scratch_<TASK>_<date>/`. Из хвоста `Пишет:` отбрасываются токены с пробелом или знаком параграфа: рядом с путями там стоят ссылки вида `` `ADR-081 §8` ``, и две задачи, цитирующие один ADR, дали бы пересечение, то есть заблокировали бы законный запуск. Ложное срабатывание здесь не безобидно: оно учит игнорировать проверку. accepted (архитектор).

  §5 **Отказ остаётся отказом.** Нет ни брифа, ни строк мандата — `RC 3`; источник найден, но набор пуст — `RC 3`. Тихого пропуска нет ни в одной ветке (`ADR-021 §2`). accepted (архитектор).

  §6 **Приёмка — шесть кейсов по РЕАЛЬНОМУ содержимому репо, синтетической фикстуры нет намеренно** (`05_CONVENTIONS` Часть I, расширение `ADR-074`: замер, обосновывающий механическую проверку, обязан идти по реальному содержимому, иначе доказано лишь, что проверка умеет краснеть).
