## NEW_DECISIONS  (→ append в 06_DECISIONS_LOG.md как ADR; "нет" если нет)
- ADR-089: Атрибуция контрагента в SCD2-справочнике матчит оракул: текущий вид, не снимок на дату сделки
  Контекст: `PARITY-SCD2-ATTRIBUTION` (`ADR-085 §8`, 2026-07-30) — второе из двух решений-предусловий
  построчных сверок реестра паритета. Custom Query `msklad_counterparty_returns` (и любая денормализация
  `core.dim_counterparties` — universal-правило `02_ERP_CONTRACTS.md:409`, `AND scd2_is_current = TRUE`)
  присваивает историческим продажам сегодняшнее имя и страну контрагента, тогда как SCD2-версионирование
  справочника (`scd2_valid_from/to`) существует ровно для обратного — чтобы уметь восстановить состояние
  на дату. Бьёт по разрезу «страны», названному Треком A (`reference/client_concerns_2026-07.md`).
  Решение:
  §1 Факт о модели данных МойСклада: `country` — «кастомное поле» (`02_ERP_CONTRACTS.md:154`) сущности
  контрагента, не поле документа продажи/возврата — схемы `core.fact_sales`/`core.fact_returns`
  (`02_ERP_CONTRACTS.md:18-22`, `94-98`) несут только `agent_id` (FK), колонки `country` там нет.
  МойСклад структурно не хранит атрибуты контрагента ПО ДОКУМЕНТУ — только по сущности контрагента,
  одним текущим значением. accepted (архитектор).
  §2 Наше собственное SCD2 на `dim_counterparties` — не отражение версионирования внутри МойСклада, а
  артефакт нашего пайплайна: `cf-dim` детектирует изменение при ПОСЛЕДУЮЩЕМ суточном прогоне и создаёт
  вторую запись (`01_ARCHITECTURE.md:392`, RB-22). МойСклад сам никогда не предъявляет клиенту «страну
  контрагента на дату сделки» — этой величины не существует нигде в его собственной модели данных,
  включая интерфейс и report-API. accepted (архитектор).
  §3 Отсюда: разрез «страна»/«имя контрагента» оракула (`ADR-067` — то, что рисует интерфейс МойСклада)
  для ЛЮБОГО периода, включая исторический, есть текущее состояние сущности контрагента — оракулу
  нечем показать иное. Правило-мост «снимок на дату сделки» дало бы число, НЕ воспроизводимое клиентом
  никаким запросом к МойСкладу — то есть нарушило бы главный принцип (`00_CHARTER §главный принцип`)
  сильнее, чем решает. Правило-мост фиксируется как (b): «текущий вид контрагента» — осознанное
  свойство поверхности, обязательное условие паритета «по цифрам» с оракулом, не примирение половин.
  accepted (архитектор).
  §4 Действующий JOIN `AND scd2_is_current = TRUE` (`02_ERP_CONTRACTS.md:157/409`) признаётся
  КОРРЕКТНЫМ по существу, правки кода/запросов не требуется. `PARITY-SCD2-ATTRIBUTION` закрывается этим
  решением, класс B не открывается. accepted (архитектор).
  §5 Остаточное ограничение решения, названное явно: аргумент §1-§3 структурный (custom-поле живёт на
  сущности, документ несёт только FK), не прямое наблюдение отображения МойСклада. Отдельный, более
  узкий случай — замороженные реквизиты в печатных формах документов (если МойСклад такое практикует
  для каких-то полей) — этим решением не покрывается и не отменяется; различитель под него не заводится
  проактивно, потому что цена ошибки для АНАЛИТИЧЕСКОГО разреза «страна»/«имя» уже определена §3, и
  никакое наблюдение печатной формы эту цену не меняет для этого разреза. accepted (архитектор).
