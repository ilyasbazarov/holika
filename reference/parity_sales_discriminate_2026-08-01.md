## Шаг 2 — офлайн-пересчёт `Σ demand.sum` по суткам документа

Источник: `reference/_scratch_PARITY-CHECK-SALES-RETURNS_2026-08-01/demand_page_0.json` (100
документов) + `demand_page_100.json` (27 документов) = 127 документов, без сети. Скрипт —

**Метод:** для каждого документа — `sum` (минорные единицы) ÷ 100 × курс; курс = `rate.value`
документа, если поле присутствует (5 из 127 документов), иначе текущий курс валюты документа
(`entity/currency.rate`: KGS=1.0, USD=90.0, RUB=1.135) — правило `ADR-010`
(`02_ERP_CONTRACTS.md §валюты`). Сутки документа — `DATE(moment_utc + 6 часов)` (Asia/Bishkek,
API отдаёт UTC, `ADR-088 §3`, правило продаж).

**Контроль:** итоговая сумма скрипта — `91 892 755,66` — совпадает до копейки с числом `Q-98`
(`ADR-097 §1`) и с числом, независимо посчитанным сессией `PARITY-CHECK-SALES-RETURNS`
(`step5d_currency_breakdown.log:20`, `revenue_converted_kgs=91892755.66`). Две независимые сессии,
два разных скрипта — одно число.

## Шаг 4 — протухание снимка (`_loaded_at` vs `updated`)

Полный расчёт — `reference/_scratch_PARITY-SALES-DISCRIMINATE_2026-08-01/step4_staleness_check.log`.

- `updated` 127 документов `entity/demand` (из уже скачанных заголовков): диапазон
  `2026-05-12 14:48:11.442` … `2026-07-28 11:50:59.677` (UTC).
- `_loaded_at` майских строк `core` (шаг 1а): диапазон `2026-05-14 03:01:59` …
  `2026-07-19 01:08:45`, основная масса (99,5% строк) — одним прогоном `2026-07-19`.
- **6 из 127 документов (4,7%) несут `updated` ПОЗЖЕ основной загрузки `core` (`2026-07-19`)** —
  то есть по этим документам снимок `core` устарел относительно последней правки МойСклада:

  | `id` | `updated` (UTC) |
  |---|---|
  | `114e19b0-5814-11f1-0a80-1b8001911765` | 2026-07-28 11:50:59.677 |
  | `14b7d25d-4b58-11f1-0a80-0fc70131e06c` | 2026-07-21 14:05:18.656 |
  | `39f47691-543b-11f1-0a80-1b7a00525695` | 2026-07-21 14:05:43.577 |
  | `413cbc1e-4c30-11f1-0a80-0fc701c8a407` | 2026-07-25 09:10:44.234 |
  | `d8225690-46b0-11f1-0a80-103e001f8806` | 2026-07-22 10:55:29.998 |
  | `eebbb88b-5a77-11f1-0a80-1b890060184b` | 2026-07-21 12:16:51.661 |

- Оставшиеся 121 из 127 документов (95,3%) несут `updated` ДО или в день основной загрузки
  `core` (`2026-07-19`) — по ним снимок не протух относительно `updated`.
- **Ограничение вывода:** сопоставление здесь — `updated` документа против даты массовой загрузки
  `core`, не построчное совпадение документ↔строка `core` (у `core.fact_sales_profit` нет прямого
  FK на `demand_id`, только `transaction_id = MD5(demand_id + position_id)`, необратимый хэш).
  Различить, какие ИМЕННО строки `core` относятся к этим 6 документам, этим замером не сделано.
