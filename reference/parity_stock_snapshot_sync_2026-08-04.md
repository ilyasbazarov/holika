## Шаг 1a — выбор кандидата ретроспективного момента

`bq query` (read-only), окно внутри `run_step1.log`, партиция «неделю назад»
(`DATE_SUB(CURRENT_DATE("Asia/Bishkek"), INTERVAL 7 DAY)` от даты запуска `2026-08-04` →
`2026-07-28`):

```json
[
  {
    "date_snapshot": "2026-07-28",
    "max_loaded_at": "2026-07-27 21:00:03",
    "min_loaded_at": "2026-07-27 21:00:03",
    "n_rows": "330"
  }
]
```

**Кандидат `moment` = `2026-07-27 21:00:03`** (сырое значение `_loaded_at` этой партиции, без
преобразования часового пояса — для пробы формата важна только удалённость от текущего момента,
не точная семантика зоны). Удалённость от момента вызова (`2026-08-04T15:17Z`) — **7 суток с
хвостиком**, что на два порядка больше наблюдённой суточной амплитуды оборота (`5 355,00` штук за
`3ч36м`, `reference/parity_stock_rowwise_2026-08-04.md`), то есть заведомо достаточно далеко, чтобы
совпадение ответов не могло быть прочитано как «остаток не менялся».

## Шаг 1d — сравнение тел ответов (построчно, не только по агрегату)

- **Контроль 1 vs Контроль 2:** побайтово идентичны (`diff -q` → `IDENTICAL`). За 7 секунд элапса
  оборот отсутствует — ожидаемо для read-only контроля в одну минуту.
- **Проба vs Контроль 1:** тела **различаются побайтово** (`740 964` vs `740 931` байт), но разница
  целиком объясняется одним полем — эхо-URL в `meta.href` (пробный URL несёт `&moment=…`,
  контрольный — нет). Построчная сверка всех `326` строк по ключу `meta.href` товара (не путать с
  `meta.href` верхнего уровня ответа) дала **0 расхождений** в `stock` — ни одной строки с разным
  значением, ни одной строки, отсутствующей в одном из двух ответов. Проверено программно
  (см. команду ниже), не визуально.

```
control1 keys: dict_keys(['context', 'meta', 'rows'])
probe keys:    dict_keys(['context', 'meta', 'rows'])
n_diffs (по построчному stock, ключ — meta.href товара): 0
```

Единственное различие двух тел:

```
control1 meta.href: .../report/stock/all?stockMode=all&quantityMode=all&limit=1000
probe    meta.href: .../report/stock/all?stockMode=all&quantityMode=all&limit=1000&moment=2026-07-27%2021%3A00%3A03
```

То есть API принял параметр `moment` без ошибки (это не `400`), эхом вернул его в собственном
`meta.href`, но **данные, которые он отдал, не изменились ни на одну строку и ни на одну штуку**
относительно контроля — при том что за прошедшую неделю (партиция `2026-07-28` того же датасета
несёт другой набор строк с другими остатками, что подтверждается независимо построчной сверкой
`PARITY-STOCK-ROWWISE` за один день).

## Вердикт шага 1: ОТРИЦАТЕЛЬНО

**Параметр `moment` С ЭТИМ ИМЕНЕМ report/stock/all не принимает содержательно.** API возвращает
`200` и эхо параметра в `meta.href`, но фактические данные (`rows[].stock` по каждому товару)
идентичны контролю — при кандидате, отстоящем на 7 суток, то есть на два порядка дальше суточной
амплитуды оборота (см. обоснование выбора кандидата в шаге 1a). Совпадение ответов при столь
далёком кандидате исключает прочтение «остаток за неделю не менялся» — по построению замера
(`ADR-123 §8` пункт 1) остаётся только прочтение «параметр проигнорирован».

**Границы вывода — дословно, как требует бриф:**

> Этот результат означает РОВНО «параметр `moment` (в проверенном формате `YYYY-MM-DD HH:MM:SS`,
> tested as query-string `moment=`) сервером `report/stock/all` НЕ учитывается» и **НЕ означает**
> «МойСклад не умеет отдавать остатки задним числом». Не проверено и не может быть выведено из
> этого замера:
> - имя параметра могло быть неверным (`moment` — рабочая гипотеза по аналогии с
>   `report/profit/*`, не документированный факт, см. бриф §Шаг 1 п.2);
> - формат значения параметра мог быть неверным (испробован ровно один формат);
> - endpoint `report/stock/bystore` (упомянутый в реестре паритета как альтернативный источник)
>   не пробовался;
> - публичная документация API МойСклада инструменту недоступна, поэтому исчерпывающая проверка
>   «умеет/не умеет в принципе» им не производится ни при каком результате пробы.
>
> Окончательное закрытие вопроса «умеет ли API отдавать остатки задним числом» остаётся за
> владельцем (один взгляд в документацию эндпоинта), как и предписано брифом.
