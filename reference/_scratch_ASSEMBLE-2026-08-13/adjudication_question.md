# Вопрос архитектору — сборка буфера 2026-08-13, три развилки в четырёх блоках

**Контекст.** Проход сборки на `HEAD=8f50eaa`. Шаг 0 (слияние веток `s/*`) выполнен: все семь
веток слиты в `main` без конфликтов кода — `DQ-CFDQ-DEPLOY`, `MARTS-BUILD-STAMP`,
`PARITY-CLIENT-JULY-RECHECK` оказались уже предками `main` (слияние — no-op); четыре ветки внесли
новые коммиты слияния: `DQ-FRESHNESS-COVERAGE`, `INGEST-CURRENCY-ASSERT`, `MARTS-BUILD-STAMP-PREP`,
`MARTS-STAMP-FORM-ADJ`. После слияния `reference/_inbox/` несёт ПЯТЬ файлов-блоков, все датированы
`2026-08-13`. Блок `session_PARITY-CLIENT-JULY-RECHECK_2026-08-13.md` уже разобран отдельным
апрувом владельца (маркер `[применено сессией]` вне словаря `_ASSEMBLER.md §3a` принят как
легитимный по прецеденту `ADR-145`/`ADR-146`/`ADR-152`/`ADR-173`) — этот блок в развилках ниже не
участвует, его номера ADR (`ADR-174`–`ADR-176`) и текст готовы к применению отдельно.

Три развилки — по оставшимся четырём блокам.

## Развилка 1 — `DQ-FRESHNESS-WIRE` просит сборщика назначить статус

`session_DQ-FRESHNESS-WIRE_2026-08-13.md`, раздел `## STATE_PATCH`:

> Строка `DQ-FRESHNESS-WIRE` (`07_GAPS.md`) переводится из `READY` в статус, который назначит
> сборка — проверка проведена: ...

Роль сборщика (`_ASSEMBLER.md §1`): «не решает и не адъюдицирует — суждение это архитектор».
Присвоение итогового статуса задаче по существу работы — суждение, не техническая подстановка
номера ADR. Сборщик не вправе выбрать между `DONE`/`PARTIAL`/иным сам.

**Факты блока, релевантные выбору:** все двенадцать функций свежести подключены к `CHECKS`
(список вырос с 7 до 19 пар); `python3 -m py_compile` → `rc=0`; грep-проверка подтвердила, что ни
одна из шести технических проверок не может вернуть `False`; ничего не задеплоено, живых вызовов
не было. Задача явно названа классом A (подготовка); соседняя строка `DQ-FRESHNESS-WIRE, деплой`
(класс B) отдельно и остаётся `READY`, мандат не выдан.

**Вопрос:** какой статус присвоить строке `DQ-FRESHNESS-WIRE` (подготовка) в `07_GAPS.md`/
`07_STATE.md` — `DONE` (подготовка закрыта фактом, аналогично `INGEST-CURRENCY-ASSERT` в этом же
буфере, который сам написал `READY → DONE (шаги 1-2)`) или другой статус, и почему?

## Развилка 2 — правки блока `MARTS-STAMP-FORM-ADJ` частично уже стоят в репо

`session_MARTS-STAMP-FORM-ADJ_2026-08-13.md` несёт два `NEW_DECISIONS` с пунктами `[сейчас]` на
`07_GAPS.md`/`07_STATE.md`. Проверка текущего состояния репо (`HEAD=8f50eaa`, до применения этого
блока) показала:

- **Уже фактически применено** (без маркера, указывающего на это): `07_GAPS.md` строка
  `DQ-FRESHNESS-WIRE` (создана прежде, видимо напрямую владельцем — коммит `47e6511`, сессия
  `PARITY-CLIENT-JULY-RECHECK`) уже несёт содержание, совпадающее по фактам с находкой
  `MARTS-STAMP-FORM-ADJ` (двенадцать функций, семь пар в `CHECKS`, `run_id=1786564802.7168841`).
- **Ещё НЕ применено:** снятие предметного гейта строки `MARTS-BUILD-STAMP` в `07_GAPS.md`/
  `07_STATE.md §Открытые вопросы` (текущий текст всё ещё несёт «выбор варианта — owner-gated»,
  решение `MARTS-STAMP-FORM-ADJ` о варианте «две колонки» туда не попало); дописка в
  `07_ARCHIVE.md` строку `DQ-FRESHNESS-COVERAGE` о фактическом объёме исполнения (что 12 функций
  не были подключены к `CHECKS` на момент архивации) — в архиве такой дописки нет.

Блок не несёт маркера `[применено сессией]` ни на одном из своих пунктов `[сейчас]` — по
`_ASSEMBLER.md §3a` пункт `[сейчас]` обязан быть применим сборщиком этим же коммитом, и
расхождение (часть уже стоит в репо) есть находка, не входящая в словарь.

**Вопрос:** для пунктов `[сейчас]` этого блока, чьё содержание уже фактически совпадает с текущим
репо — считать их исполненными задним числом (по аналогии с `[применено сессией]`) и не трогать
повторно, а применить только два реально отсутствующих пункта (снятие гейта `MARTS-BUILD-STAMP`,
дописка в архив про `DQ-FRESHNESS-COVERAGE»)? Или трактовать иначе?

**Смежный вопрос (Стенд-ап).** Три из пяти блоков буфера несут собственный блок «Стенд-ап»
(`MARTS-STAMP-FORM-ADJ`, `MARTS-BUILD-STAMP-PREP`, `PARITY-CLIENT-JULY-RECHECK`). Правило
`_ASSEMBLER.md §4` («стенд-ап берётся из ПОСЛЕДНЕГО по порядку блока, остальные отбрасываются
полностью») при порядке по дате+алфавиту (все блоки `2026-08-13`) даёт `PARITY-CLIENT-JULY-RECHECK`
последним — его Стенд-ап уже применён отдельным апрувом. Это оставляет Стенд-апы `MARTS-STAMP-FORM-ADJ`
и `MARTS-BUILD-STAMP-PREP` отброшенными ПОЛНОСТЬЮ по букве правила. Подтвердите, что это
корректно и в этом случае — правило написано для одновременных параллельных сессий, не для цепочки
зависимых блоков одного дня, но текст правила исключений не делает.
