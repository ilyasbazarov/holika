## 3. Два расхождения с принятым решением — названы, не исправлены

**(i) Репозиторий публичный, решение говорило «приватный».** `ADR-109 §7` фиксирует выбор владельца
как «приватный GitHub `holika-prod`». Замер даёт `isPrivate: false`. В выложенном `main.py`
`cf-finance` секретов-значений нет (проект читает их через Secret Manager по имени), но публично
доступны идентификатор проекта GCP, адреса служебных аккаунтов, имена бакетов и датасетов, имя
секрета и внутренняя логика конвейера. Это **не блокер** и не инцидент; это расхождение факта с
принятым решением, и снимается оно одним переключателем видимости. Решение — владельца: либо
переключить видимость, либо изменить решение `ADR-109 §7` явным ADR. Тихого примирения не делается
(`00_CHARTER §главный принцип`).

**(ii) Ветка по умолчанию `master`, не `main`.** Ни одно решение проекта имени ветки код-репо не
называет — расхождением с решением это не является, фиксируется как факт для будущих скриптов
деплоя, которые иначе будут искать `main`.

## 4. Почему факт простоял незамеченным двое суток (класс дефекта, не упрёк)

Строка мандата и строка реестра для шага 2b несли формулировку «исполняет владелец, инструменту не
отдаётся (`ADR-076 §1`)». Она верна по существу — `git push` вовне остаётся за владельцем. Но она
читалась сессиями как «состояние этого шага инструменту недоступно», и потому **ни одна сессия ни
разу не проверила, исполнен ли он.** Проверка стоит одного read-only вызова без секретов и без
записи (`gh repo view`), то есть полностью внутри класса A.

Обобщение, применимое шире одной строки: **«действие за владельцем» и «состояние непроверяемо
инструментом» — два разных свойства, и в реестре они молча слиты в одно.** Тот же признак несут
сегодня как минимум: правки в интерфейсе Looker Studio (действие владельца — но результат
проверяется запросом к витрине, а не только устным подтверждением, ср.
`LS-INVENTORY-EXPLICIT-COLUMNS`, где read-back остался устным) и `MSKLAD-TZ-PROPOSAL`.

Цена конкретно этого инстанса измерима: гейт `ADR-065` объявлен `ADR-109 §5` единственным гейтом
всего деплойного потока; он стоял снятым `2026-08-01T16:35:55Z`, а очередь готовых правок числилась
заблокированной по `2026-08-03`. Двое суток простоя очереди на бухгалтерии.

**Предложение (proposed, требует апрува):** строка реестра, у которой действие за владельцем,
обязана нести отдельным полем **способ проверки состояния** — либо конкретный read-only вызов, либо
явное «проверке инструментом не поддаётся» с причиной. Строка без этого поля есть строка, которая
может простоять исполненной неопределённо долго.

- Видимость репозитория **не менялась** этой сессией: смена настроек репозитория есть действие
  владельца, вопрос вынесен в §3(i).
