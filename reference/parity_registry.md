# /reference/parity_registry.md — Реестр паритета (страница/отчёт МойСклад ↔ витрина/страница Looker Studio)

**Задача:** `PARITY-REGISTRY`, discovery-часть (класс B, мандат `ADR-076 §3a`).
**Основание:** `ADR-067 §5a/§5b`, `ADR-068 §3`, `ADR-069 §1/§4`.
**Что покрывает этот файл:** инвентарь пар из обоих сидов (`01_ARCHITECTURE.md §потребители` таблица PR-39; `reference/client_concerns_2026-07.md` треки A/Б), правило-мост там, где оно выводится из уже принятых ADR/SQL репо, endpoint report-API (Шаг 2, детали — `reference/parity_report_api_2026-07-28.md`), покрытие-с-даты, статус сходимости по существующим артефактам.
**Чего этот файл НЕ делает** (`ADR-076 §4`): не адъюдицирует НОВЫЕ правила моста. Где правило не выводится напрямую из принятого ADR/SQL — строка помечена «требуется», не заполнена предположением.
**Мост** — только уровень (b) паритета (`ADR-068 §1`): совпадение итогов/строк через опубликованное правило, не пиксельное совпадение страниц.
**DERIVED вне паритета** (`ADR-067 §4`): `total_sum_usd`/`revenue_usd`/`cogs_usd`/`margin_usd`/`gmroi`/ABC-XYZ и прочие производные от `dim_fx_rates`-конвертации в реестр НЕ включаются как объект сверки; сверка — только на KGS-величинах до производных.
**Якорь глубины паритета:** `2026-05-01` (`ADR-069 §2`) — используется во всех строках, где иное не обосновано фактом репо.

## Раздел «вне реестра»

Поверхности, у которых нет пары (страницы LS без марта-аналога МойСклад, либо марта без страницы LS), с основанием по каждой (`ADR-069 §3`/`04_ROADMAP §Финиш Epic-1` — расширение реестра не самодеятельность):

| Поверхность | Основание отсутствия пары |
|---|---|
| `marts.weight_flow` (страница LS «Склад», `msklad_weight_flow`) | Оракула на стороне МойСклад нет ни на одном уровне (i/ii/iii): вес — расчётный KPI (`quantity × dim_products.weight`), в report-API и entity-API МойСклада весового отчёта/поля агрегата не существует. Пара не заводится за отсутствием стороны для сверки, не как самодеятельное расширение |
| `marts.abc_xyz` | Нет назначенной страницы LS в замороженном источнике PR-39 (`01 §потребители`, PR-30). Аналитический март без потребителя на момент источника |
| `marts.gmroi` | Нет назначенной страницы LS (PR-30), тот же источник исключения |
| `marts.gmroi_by_folder` | Нет назначенной страницы LS (PR-30); дополнительно наследует `rate_kgs_per_usd` из `marts.gmroi`, собственного запроса к `dim_fx_rates` не имеет (`ADR-050 §3`) |
| `marts.supplier_price_history` | Нет назначенной страницы LS (PR-30) |

Все пять поверхностей выше учтены явно (не пропущены молча), расширение реестра под них — решение владельца, не производится этой сессией.

## Плашка «вне паритета (до 2026-05)» (Шаг 4, `ADR-069 §4`)

**Назначенный текст плашки:** «Данные до 2026-05-01 — вне паритета с МойСклад: сверка с эталоном МойСклад не производилась, показатели за этот период не гарантированы к сходимости».

**Условие показа:** строка/точка на графике датирована ранее `2026-05-01`.

**Страницы LS — носители плашки** (поверхности с историческим рядом дат в отображении):

| Страница LS | Источник | Основание — почему плашка нужна |
|---|---|---|
| Инвестор | `msklad_sales_overview` | Динамика по датам — на графике возможны точки ранее `2026-05-01` |
| Операционка | `msklad_sales_overview`, `msklad_counterparty_returns` | То же — динамика контрагентов/стран, возвраты по датам |
| Расходы | `msklad_expenses` | Помесячная/понедельная динамика расходов — исторический ряд |
| Склад (график веса) | `msklad_weight_flow` | Динамика приёма/отгрузки по датам |

**Страницы/витрины — плашка НЕ нужна** (ранняя история не отображается вовсе — снимок «на сейчас», не временной ряд):

| Витрина | Основание |
|---|---|
| `marts.inventory_health` | `date_snapshot = MAX(...)` — единственный текущий снапшот, исторических точек на странице нет |
| `marts.in_transit` | Текущее состояние открытых заказов поставщику, не временной ряд |
| `marts.customer_invoices_ar` | «Custom Query, без date range — snapshot» (`03_PIPELINE_SPEC §marts.customer_invoices_ar`); `earliest_invoice_date`/`latest_invoice_date` — атрибуты строки, не ось графика |

**Применение плашки в Looker Studio — ручное действие владельца, в эту задачу не входит** (сама задача выдаёт только текст и адресный список).

## Гэпы (Шаг 5)

Всё, что реестр не смог заполнить по состоянию репо, отражено дважды: строкой «требуется» в таблице выше и `Q`-строкой в `STATE_PATCH` (см. session-блок коммита). Сводка:

1. **Мост `sales_overview` (Инвестор/Операционка) не выведен** — соответствие `revenue_kgs`/`cogs_kgs`/`margin_kgs` полям `report/profit/byproduct`/`bycounterparty` не проверено построчно → `Q-78`.
2. **`msklad_counterparty_returns` (Трек A) — источник в репо не найден** (ни SQL, ни правило), эталон `recon_2026-05.md` не посеян → `Q-79` (частично дублирует известный DEFER `ADR-005 §5`, формализуется отдельной строкой для реестра).
3. **Мост `inventory_health` частично не выведен** — построчная сверка `stock` с `report/stock/all` не выполнена; расчётные флаги (`is_low_stock`/`is_toxic`/`coverage_days_*`) не являются ORACLE-величиной по построению → `Q-80`.
4. **Мост `in_transit` (SQL выведен, численно не сверен)** — фильтр статуса зафиксирован из SQL, но 0,00-сверка с `entity/purchaseorder` не проведена → `Q-81`.
5. **Мост `customer_invoices_ar` не выведен** — соответствие полей `entity/invoiceout` (`sum`/`payedSum`/`state.name`) агрегатам SQL не проверено → `Q-82`.
