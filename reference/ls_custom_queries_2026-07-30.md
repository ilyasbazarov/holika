Инструменту интерфейс Looker Studio недоступен (`ADR-085 §9`), поэтому инвентарь снимается владельцем,
а репо хранит снимок текста.

из `SOURCE-MAP-REST §6` (объект `msklad_counterparty_returns` инструментами BigQuery не находится,
потому что живёт не в BigQuery, а в Looker Studio).

## Исключения §2 (`ADR-087`): снимок на момент

Задача `LS-PERIOD-CONTRACT`, пункт (а). `ADR-087 §2` разрешает ровно один класс исключения из
правила «период Custom Query берётся из параметров дашборда `@DS_START_DATE`/`@DS_END_DATE`» —
величину, которая по своей природе периода не имеет. Оба исключения ниже объявлены строкой
инвентаря; вторая половина объявления (`ADR-087 §2`) — подпись на самой странице дашборда — за
владельцем в интерфейсе Looker Studio, этой сессии недоступна.

| Источник | Страница | Класс | Проверка текстом запроса |
|---|---|---|---|
| `msklad_customer_invoices_ar` | Операционка | задолженность на сейчас | `reference/sql/msklad_customer_invoices_ar.sql` не читает `@DS_START_DATE`/`@DS_END_DATE` и не несёт временного фильтра — `WHERE` фильтрует только `total_unpaid_kgs`/`state_name`, дата нигде не участвует |
| `msklad_inventory_latest` | Склад | остатки на складе на сейчас | `reference/sql/msklad_inventory_latest.sql` не читает параметры дашборда; период задан подзапросом `WHERE date_snapshot = (SELECT MAX(date_snapshot) FROM marts.inventory_health)` — последний доступный снимок, не окно |

Расхождения объявленного с текстом запроса (`ADR-087 §4`) не найдено ни у одного из двух.

## Страница «Склад», источник `msklad_inventory_latest`

Графики на этом источнике (снято владельцем 2026-07-30): «Токсичные товары»,
«Замороженный капитал KGS», «Товаров в OOS», «Токсичный сток», «Замороженный капитал по брендам»,
«OOS — нет товара на складе», «Мало запаса (не OOS)». Семь штук на одном запросе.

Поля графика «Токсичные товары», отображаемые имена: Бренд, Товар, Остаток, Дней на складе,
Замороженный капитал KGS, Запас в днях (сглаженный), Замороженный капитал (USD). Поля остальных
шести графиков не снимались и сниматься не будут, см. вывод ниже.

Соответствие колонкам `marts.inventory_health` (32 колонки по
`reference/schema_dump_2026-07-28.md`) установлено не полностью:

| Отображаемое имя | Колонка | Статус |
|---|---|---|
| Товар | `product_name` | вероятно, единственный кандидат |
| Остаток | `stock` | вероятно, единственный кандидат |
| Дней на складе | `stock_days` | вероятно, единственный кандидат |
| Замороженный капитал KGS | `frozen_capital_kgs` | вероятно, единственный кандидат |
| Замороженный капитал (USD) | `frozen_capital_usd` | вероятно, единственный кандидат |
| Бренд | `product_folder` ? | НЕ УСТАНОВЛЕНО, колонки с именем бренда в схеме нет |
| Запас в днях (сглаженный) | `coverage_days_true_adt` либо `coverage_days_90d_calendar` | НЕ УСТАНОВЛЕНО, два кандидата |

Вывод для `Q-87`: аудит «какие колонки используются» негоден как способ закрытия. Семь графиков на
одном источнике, два отображаемых имени без однозначного кандидата в схеме, и любой новый график
ломал бы такой список задним числом. `ADR-087 §7` закрывает вопрос иначе: `SELECT *` заменяется
ПОЛНЫМ списком колонок таблицы, снятым с живой схемы в момент правки. Соответствие отображаемых
имён колонкам при этом устанавливать не требуется.

**Отдельно:** `marts.inventory_health` несёт колонку `rate_kgs_per_usd`, то есть курс в этом марте
приходит из данных. Custom Query `fact_returns` при этом конвертирует литералом `87.4`. Правильный
образец лежит рядом, в том же дашборде.

## Наблюдения по составу (факты из текста запросов, не суждения)

1. **Параметры периода дашборда честно используют два запроса из пяти.** `msklad_expenses` полностью,
   `msklad_counterparty_returns` только в части продаж. Остальные три работают своим окном либо без окна.
   Следствие: дата-контрол дашборда управляет не всей страницей.
2. **Слой ядра и слой марта смешаны на одном дашборде.** Два запроса читают `core.*` напрямую
   (`msklad_counterparty_returns`, `fact_returns`), три читают `marts.*`. Правило моста реестра паритета
   описывает core-слой (`ADR-079 §2`), поэтому для запросов к `marts.*` оракул и правило моста
   разные, и это не одна и та же сверка.
3. **Курс USD присутствует в двух формах.** `marts.expenses` несёт готовую колонку `total_sum_usd`,
   `fact_returns` конвертирует литералом `87.4` внутри запроса Looker Studio. Вторая форма ни к
   `core.dim_fx_rates`, ни к политике конвертации не привязана.
4. **Поле `rate_kgs_per_usd` в `fact_returns` тождественно `total_return_sum_usd`.**
   `SUM(sum_kgs) / 87.4` и `SUM(sum_kgs / 87.4)` дают одно и то же число, то есть колонка с именем
   курса несёт сумму возвратов в USD. Проверка арифметическая, замера не требует.
5. **`msklad_inventory_latest` идёт через `SELECT *`.** Состав колонок клиентской поверхности задаётся
   схемой `marts.inventory_health`, а не решением.

## Что осталось за владельцем

По инвентарю задачи `LS-QUERY-SNAPSHOT` — ничего: закрыта 2026-07-30, строка перенесена в
`07_ARCHIVE.md`. Правки самого дашборда идут отдельными строками реестра и исполняются владельцем
в интерфейсе: `LS-RETURNS-FX-HARDCODE`, `LS-INVENTORY-EXPLICIT-COLUMNS`.

Задача `LS-PERIOD-CONTRACT`, пункт (б): подпись на страницах «Операционка» и «Склад» о том, что
соответствующий блок показывает снимок на момент, а не период дашборда (`ADR-087 §2`) — за
владельцем в интерфейсе Looker Studio, инструменту недоступно. Пункт (а) (строки-исключения выше)
закрыт этой сессией.
