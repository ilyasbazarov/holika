## 2. Факт-проверка ИСПОЛНЕНИЕМ — пройдена. Закрыт фактом

Прогон под Python 3.9.6 (прод — `python312`): более старая версия синтаксис принимает, значит
современных конструкций, которые уронили бы `3.9`, в файле нет — обратной проблемы не бывает.

## 4. Форма чтения вложенных структур — одно новое вхождение устаревшей формы

**Канон `ADR-171 §6` для нового кода — `(x or {})`.** В патче он применён в одном месте и не
применён в другом:

| Строка | Форма | Оценка |
|---|---|---|
| `main.py:78` `rate_obj = row.get("rate") or {}` | канон | ✅ |
| `main.py:80` `parse_href(rate_obj.get("currency"))` | `parse_href` сам защищён `(meta_obj or {})` | ✅ |
| `main.py:33` `url = resp_json.get("meta", {}).get("nextHref")` | **устаревшая форма в НОВОЙ функции** | ⚠️ |

Класс дефекта живой, а не теоретический — замерено в этой сессии исполнением:

```
parse_href({'meta': None}) → ИСКЛЮЧЕНИЕ AttributeError: 'NoneType' object has no attribute 'get'
```

То есть при `"meta": null` в ответе конструкция падает. Смягчающее: ровно та же строка уже
существует в этом файле (`main.py:109`) и работает в проде ежедневно с июня на соседнем
эндпоинте — вероятность реализации близка к нулю. Отягчающее: строка `33` — НОВЫЙ код, а канон
писан именно для нового.

## 5. Поведение при отказе внешнего запроса — НЕ ЗАКРЫТ

`_fetch_currency_map` идёт к `entity/currency` **в начале** `run_etl()`, до загрузки платежей:

```python
resp = requests.get(url, headers=headers)     # main.py:28 — ни timeout, ни raise_for_status, ни ретрая
time.sleep(0.25)                              # пауза по 02_ERP_CONTRACTS §поведение API соблюдена ✅
resp_json = resp.json()
```

**Сравнение с идиомами того же деплойного объекта** (это и есть различитель, а не вкусовщина):
в `cf-finance` СОСУЩЕСТВУЮТ две идиомы, и патч скопировал слабейшую.

| Место | `timeout` | `raise_for_status` | ретрай |
|---|---|---|---|
| `main.py:66` — существующий запрос в `run_etl()` | нет | нет | нет |
| `invoices.py:63-70` — модуль, задеплоенный в ЭТОЙ ЖЕ функции 2026-08-03 | **`timeout=TIMEOUT`** | **есть** | **есть** (`tenacity`) |
| `main.py:28` — НОВЫЙ код патча | нет | нет | нет |

**Три конкретных исхода отказа источника, ни один не гипотетичен:**

1. **Ответ не-JSON** (502/страница прокси) → `resp.json()` бросает исключение → `run_etl()` падает
   ДО загрузки платежей. Раньше первой точкой отказа была сама выгрузка платежей; теперь их две.
2. **Ответ JSON с ошибкой** (401/429) → `rows` пуст → карта валют пуста → `iso_code` равен `None`
   у КАЖДОЙ строки → детекция ложно срабатывает на всех платежах. Арифметика не страдает,
   но журнал заполняется ложными предупреждениями, то есть проверка, поставленная ради сигнала,
   даёт шум вместо сигнала.
3. **Соединение зависло** — таймаута нет, поэтому вызов висит до `attemptDeadline=1800s`
   Scheduler'а; суточная загрузка платежей в этот день не происходит.

**Требуемая правка — три строки, только внутри новой функции:**

```python
resp = requests.get(url, headers=headers, timeout=90)   # 90 c — 02_ERP_CONTRACTS §поведение API
resp.raise_for_status()
...
url = (resp_json.get("meta") or {}).get("nextHref")      # закрывает и пункт 4
```

Существующий `main.py:66` **НЕ трогать** — это ретрофит, он вне объёма и `ADR-171 §6` его прямо
не требует.

## 6. Неизменность арифметики — закрыт фактом

Полный дифф патча (`step2_diff.patch`, `43` строки в `main.py`): единственная удалённая строка —
пустая строка с хвостовыми пробелами. Строка, считающая сумму (`main.py:105`,
`… * ((row.get("rate") or {}).get("value") or 1.0)`), присутствует в диффе только как контекст.
`invoices.py`, `requirements.txt`, `trigger_marts()`, диспетчер `main()` не тронуты; режим
`invoices` патчем не затрагивается вовсе — `_fetch_currency_map` вызывается только из `run_etl()`.

Побочно подтверждено: находка `ADR-029 §1` (`or 1.0` вместо падения) в строке `105` остаётся
как была — эта сессия её НЕ чинит, решение о ней не принималось и в объём выезда не входит.

## 7. Стоимость — закрыт с ограничением

Запрос идёт с `limit=100` и пагинацией по `nextHref`. Число валют в аккаунте клиента классом A
не измеримо (нужен `msklad-token` — класс B), поэтому точное число вызовов не устанавливается:
при ≤ 100 валютах — один вызов на прогон, дальше по одному на каждую сотню. Каденс `run_etl` —
раз в сутки (`finance-daily-update`, `0 3 * * *` Asia/Bishkek). Пауза `0.25` c соблюдена.
Порядок величины стоимости — единицы вызовов в сутки; на квоты это не влияет.
