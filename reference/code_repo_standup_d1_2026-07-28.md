## Факт: `.git` — есть, но пуст по коммитам

- `.git` **ЕСТЬ** (каталог инициализирован — `HEAD`, `objects`, `refs`, `config`, `index` присутствуют).
- `git status`: ветка `master`, **«No commits yet»**.
  - **Staged** (в индексе, не закоммичено): `main.py` (как `new file`).
  - **Modified, not staged**: `main.py` (рабочая копия разошлась с тем, что лежит в индексе).
  - **Untracked**: `.gcloudignore`, `__pycache__/`, `main.py.bak`, `main.py.pre-e1t3-mech-fx.bak`, `patch_main_finance.py`, `requirements.txt`.
- `git log --oneline --all` — **пустой вывод** (коммитов нет).
- `git rev-list --count --all` — **`0`** (число коммитов, независимое подтверждение).
- `git remote -v` — **пустой вывод** (remote не задан).
- `git branch -a` — **пустой вывод** (кроме текущей `master`, у которой нет коммитов — ветка технически ничего не показывает до первого коммита).

**Вывод одной фразой:** локальный `.git` в `/home/ilyasbazarov4/cf-finance/` — это `git init` (возможно, с одним `git add main.py`), но **ни одного коммита никогда не было сделано**. Истории версий, которую можно было бы использовать как seed, там нет — есть только пустая репо-структура поверх текущего состояния каталога на диске.

## Что это решает и что НЕТ

- **Решает:** факт состояния `.git` — есть, инициализирован, 0 коммитов, remote не задан, staged-копия `main.py` устарела относительно рабочей копии. Диск==деплой по `main.py` подтверждён повторно (не новый факт, но независимо переверифицирован).
- **НЕ решает** (вне scope этого шага, owner-gated, `ADR-017 §5`): выбор seed-from-git vs seed-from-zip. С учётом факта (0 коммитов, staged-версия устарела) seed-from-git в буквальном смысле «взять историю коммитов» невозможен — истории нет; развилка теперь по сути между «seed-from-disk/zip» и «git init заново с нуля в целевом код-репо», но это решение — не этой сессии.
- **НЕ решает:** где живёт живой код-репо (`ADR-017 §4`, вариант (a) отдельный репо — уже принят, но сам standup не исполнен).
