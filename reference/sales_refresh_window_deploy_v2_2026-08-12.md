## §6 Дополнительные факты, снижающие неопределённость (не решение, только наблюдения)

1. **За 13 часов трафика на пропатченном коде реально исполнился только ОДИН штатный часовой
   MERGE** (`job_id=104b4e42…`, `2026-08-11T17:05:48Z`, окно `7` суток): `inserted=0, deleted=0,
   updated=413`. **Удалений при штатном часовом окне не было вовсе.** Удаление специфично именно
   для расширенного 106-суточного прогона — это сужает гипотезу дефекта до логики, зависящей от
   ГЛУБИНЫ окна, а не до предиката происхождения как такового (тот же предикат отработал безопасно
   при окне 7д).
2. **27 вставленных строк не являются заменой удалённых.** Все 27 вставок датированы
   **`2026-08-12`** (сегодня) — это новые документы, появившиеся в источнике за время прогона, не
   пересозданные версии удалённых майско-июльских строк. Гипотеза «документ отредактирован, ID
   позиции изменился» этим не подтверждается: удалённые (май-июль) и вставленные (12 августа) не
   пересекаются по дате.
3. **Даты 28 удалённых оптовых строк разбросаны по всему окну** — `2026-05-07`, `05-09`, `05-26`,
   `06-03`, `06-04`, `06-15`, `07-02`, `07-11`, `07-13` (×5), `07-20`, `07-21` (×7), `07-27` (×2),
   `07-29`, `07-30` (×3). Нет кластеризации на границе страницы/даты, которая указывала бы на
   очевидный обрыв пагинации в одной точке.
4. **Сравнение живой таблицы со снимком П2 ДО второй попытки (`2026-08-12T04:52:35Z`, после ~13
   часов штатной работы патча) — полное совпадение по всем 7 каналам, 0 расхождений.** То есть
   ущерб появился ИМЕННО и ТОЛЬКО в результате MERGE `job_id=1e698e3d…` (`05:15:55Z`), не раньше.
5. **Причина, по которой 28 строк не попали в staging продаж при 106-суточной выборке — не
   установлена этой сессией.** Кандидаты (не проверены, перечислены как гипотезы для архитектора):
   (a) документы были отредактированы/аннулированы в МойСклад между временем возникновения (май-
   июль) и временем этого прогона (12 августа) — тогда удаление корректно отражает источник; (b)
   дефект пагинации/выборки `fetch_demand_positions` на длинных окнах (106д существенно больше
   ранее использовавшихся 90д) теряет отдельные позиции без видимой кластеризации; (c) что-то ещё,
   не рассмотренное. Различитель — независимый прямой запрос к `api.moysklad.ru` по нескольким
   `transaction_id` из списка §8, эта сессия его не исполняла (не входит в объявленный мандат).

## §9 Вопрос архитектору

Что решаем: третье число приёмки мандата (удалённых строк «оптовая торговля» после боевого
прогона) равно `28`, не `0`. Мандат предписывает немедленный откат при любом ненулевом значении;
владелец приостановил это предписание до вашей адъюдикации.

Варианты:
1. **Откат сейчас** — трафик на `cf-facts-00011-mab`, ветка код-репо не сливается, `28` строк
   восстанавливаются из снимка П2 или time-travel, причина расследуется отдельным discovery.
2. **Расследовать причину ДО отката** — независимый прямой запрос к `api.moysklad.ru` по нескольким
   `transaction_id` из §8 (различитель гипотез (a)/(b) §6 п.5), затем решение. Риск — код остаётся
   на трафике, штатные часовые прогоны продолжаются (по факту §6 п.1 они безопасны на 7-суточном
   окне, но это один наблюдавшийся случай).
3. **Оставить как есть, адъюдикация позже** — не рекомендуется исполнителем: живой риск §7 не
   закрыт, снимок и time-travel стареют с каждым часом штатной работы.

Рекомендация исполнителя: вариант 2 с жёстким таймбоксом (независимая проверка API — минуты, не
часы), затем откат независимо от результата, если причина не выяснена быстро — данные важнее
диагностики. Решение — за архитектором.
