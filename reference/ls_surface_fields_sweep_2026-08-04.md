# Съём состава полей графиков Looker Studio по трём неизмеренным парам реестра · 2026-08-04

**Задача:** `LS-SURFACE-FIELDS-SWEEP` (`ADR-115 §14а`). **Основание метода:** `ADR-114 §1` —
поверхностью пары реестра паритета является выведенный на дашборд ГРАФИК с конкретным составом
полей, а не Custom Query и не таблица-основа; величина, которую ничто не рисует, сверяемой
поверхностью не является. Интерфейс Looker Studio инструменту недоступен (`ADR-085 §9`) — весь
состав ниже снят владельцем в этой чат-сессии 2026-08-04 (два раунда опроса).

**Метод сопоставления полей:** отображаемое имя графика сверяется с живой схемой BigQuery
(`bq show`, снято этой сессией 2026-08-04) — совпадает с датированным снимком
`reference/schema_dump_2026-07-28.md` по всем трём таблицам-основам (`marts.inventory_health`,
`marts.in_transit`, `marts.customer_invoices_ar`), расхождений не найдено, снимок актуален.
Форма таблицы — как в `reference/ls_custom_queries_2026-07-30.md §«Страница „Склад“…»`.

### Вывод по Шагу 3

**Величина ВИДНА.** Колонка `stock` (объект паритета строки 21) выведена как поле «Остаток» на
графиках «Токсичные товары» (страница «Склад», состав снят `LS-QUERY-SNAPSHOT`) и «Мало запаса
(не OOS)» (снято этой сессией) — оба сопоставления однозначны («вероятно, единственный кандидат»).

**Статус:** частичный `CONTEXT GAP` по двум пунктам, не блокирующим вывод Шага 3: (а) формула поля
«Токсичный сток» (`toxic_stock` не найден в схеме); (б) неоднозначность колонки «Бренд» (нет

**Величина ВИДНА ЧАСТИЧНО.** Из трёх компонентов объекта паритета на экран выведен только один:
`total_unpaid_kgs` («неоплачено») — на графиках «Общая сумма дебиторки (KGS)» и «Неоплаченные

**Статус:** закрыто по всем трём графикам источника (список подтверждён владельцем как полный),
вывод не частичный `CONTEXT GAP`, а содержательный результат — величина видна не полностью.

## Сводка для `PARITY-STOCK-INTRANSIT` (`ADR-115 §13`)

`PARITY-STOCK-INTRANSIT` объединяет ровно ДВЕ пары реестра — «Остатки товаров» (строка 21) и
«Заказы в пути» (строка 22); пара «Счета покупателям» (строка 23) в него не входит (её адресует
`INVOICES-PARITY-RECHECK`, отдельная строка).

- **Остатки товаров:** величина видна (`stock`, графики «Токсичные товары» / «Мало запаса
  (не OOS)») — заход `PARITY-STOCK-SAME-DAY` НЕ рискует сравнивать невыведенную величину.
- **Заказы в пути:** величина видна (`in_transit_sum_kgs`, график «Сумма KGS в пути») — заход
  `PARITY-INTRANSIT-ROWWISE` НЕ рискует сравнивать невыведенную величину.

**Вывод: обе пары `PARITY-STOCK-INTRANSIT` разблокированы этой сессией**, ни на одной из них
класс B не рискует сверять величину, которой нет на экране (риск, названный брифом `ADR-115 §14а`,
снят по обеим).

Для третьей пары (счета покупателям, `INVOICES-PARITY-RECHECK`) находка иная и требует внимания
той задачи: сверке класса B подлежит только компонент «неоплачено» — компоненты «выставлено» и
«оплачено» на дашборде не выведены нигде, и если задача планировала сверять их, предмет сверки для
них на экране отсутствует.
