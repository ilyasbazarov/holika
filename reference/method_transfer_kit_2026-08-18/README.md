# FILE: README.md — Комплект переноса метода в новый проект

**Собран:** сессия `METHOD-TRANSFER-KIT`, 2026-08-18 (Бишкек), база — коммит `5b2d8df`.
**Назначение:** перенести рабочий конвейер холики в новый проект так, чтобы на той стороне он
заработал, а не выглядел работающим.

---

## Что делать владельцу — три шага

1. **Скопировать эту папку в корень нового репозитория** под именем `method_kit/`.
2. **Открыть новый репозиторий** в Claude Code (не холику).
3. **Вставить первым сообщением текст из `03_ПРОМТ_АРХИТЕКТОРА.md §1`**, заменив последний
   абзац на описание своего проекта.

Первая сессия закончится **вопросом**, а не готовым конвейером. Это правильно: в фазе 0 есть
три развилки, которые архитектор не вправе решить сам.

## Три вещи, которые определяют, заработает конвейер или нет

**Граница контракта.** Метод даёт остановку вместо выдумки, фиксацию знания и
воспроизводимость сессий. **Ни одна из трёх не отвечает на вопрос «правильно ли то, что мы
построили».** На него отвечает только контракт — внешний эталон, с которым выход обязан
сходиться, либо жёсткий интерфейс между слоями. Проект без контракта получит аккуратно
задокументированный, прекрасно версионированный, полностью воспроизводимый неверный результат.
Разобрано в `01_МЕТОД.md §2`.

**Механические проверки, а не правила.** Правило, которое держится только вниманием,
проигрывает конкурирующему проверяемому правилу и нарушается воспроизводимо. Это не мнение:
в холике так провалились три правила из трёх, у которых не было механизма — правило языка,
правило компактности состояния и заморозка процессного слоя. Разобрано в `01_МЕТОД.md §5.11`
и вынесено в усиление №2.

**Полный цикл, а не документы.** Метод не считается приземлённым, пока хотя бы одна реальная
задача не прошла цикл целиком: генератор → исполнитель → сборка. Всё, что не прошло цикл, есть
описание конвейера, а не конвейер. Это приёмка фазы 4 и единственная настоящая приёмка
переноса.

## Что этот комплект НЕ содержит

- **Фактов домена холики.** Ни одного: имена таблиц, цифры, названия систем — всё вычищено.
  Переносится метод, а не проект.
- **Журнала решений холики.** 192 записи про другой домен дали бы ложную трассируемость.
- **Готового ответа про границу контракта нового проекта.** Его нет и быть не может — это
  первая работа архитектора на той стороне, и она делается по материалу владельца, а не по
  аналогии.
- **Гарантии, что все семь усилений верны.** Они выведены из замеров холики и помечены
  `proposed`. Часть из них дешевле принимать, уже понимая свой домен, — это сказано по каждому.
