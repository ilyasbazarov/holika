**Запрос 1 — доля дней-копий по месяцам:**

```sql
WITH d AS (
  SELECT date, rate_kgs_per_usd,
         LAG(rate_kgs_per_usd) OVER (ORDER BY date) AS prev_rate,
         LAG(date)             OVER (ORDER BY date) AS prev_date
  FROM `msklad-bi-prod.core.dim_fx_rates`
),
f AS (
  SELECT date,
         (rate_kgs_per_usd = prev_rate AND prev_date = DATE_SUB(date, INTERVAL 1 DAY)) AS is_copy,
         FORMAT_DATE("%a", date) AS dow
  FROM d
)
SELECT FORMAT_DATE("%Y-%m", date)                      AS ym,
       COUNT(*)                                        AS days_total,
       COUNTIF(is_copy)                                AS copies_total,
       COUNTIF(is_copy AND dow NOT IN ("Sat","Sun"))   AS copies_on_weekdays
FROM f
WHERE date >= "2026-04-01"
GROUP BY 1 ORDER BY 1
```

**Запрос 2 — май-2026 построчно** (доказательная выдержка, требование `ADR-044 §2`: вердикт печатает строки, не метку):

```sql
WITH d AS (
  SELECT date, rate_kgs_per_usd,
         LAG(rate_kgs_per_usd) OVER (ORDER BY date) AS prev_rate,
         LAG(date)             OVER (ORDER BY date) AS prev_date
  FROM `msklad-bi-prod.core.dim_fx_rates`
)
SELECT date,
       FORMAT_DATE("%a", date) AS dow,
       rate_kgs_per_usd,
       (rate_kgs_per_usd = prev_rate AND prev_date = DATE_SUB(date, INTERVAL 1 DAY)) AS same_as_prev_day
FROM d
WHERE date BETWEEN "2026-05-01" AND "2026-05-31"
ORDER BY date
```

## §5 Установленные факты

1. **Май-2026 несёт ОДНО значение курса на все 31 день: `87.4205`.** Значение вошло `2026-05-01` (отличается от `2026-04-30`, `same_as_prev_day = false`) и не менялось до конца месяца. Внутримесячных изменений — ноль.
2. **Forward-fill в этой таблице — не краевой случай, а преобладающий режим.** Доля дней-копий: 63,3 % (апрель), 96,8 % (май), 86,7 % (июнь), 73,1 % (июль). Копии в **рабочие** дни — от 13 до 20 в месяц, то есть основная часть копий не объясняется непубликацией курса в выходные.
3. **Порог `ADR-053 §5` формально пройден в сторону варианта `(c′)`:** метрика «копий в рабочие дни мая-2026» = **20** при пороге «≥ 5 ⇒ `(c′)`». Одновременно измеренная величина лежит **за пределами модели**, для которой порог строился (порог предполагал forward-fill меньшинством дней) — квалификация вынесена в `§7`.
4. **Миграция источника 2026-06-03 (НБКР XLS → Bakai OpenBanking, `ADR-049 §1`) режим не изменила качественно:** до миграции — 63,3 % и 96,8 % копий, после — 86,7 % и 73,1 %. То есть это **не только историческая** особенность, а действующее состояние таблицы.
5. **В апреле и июле часть выходных дней несёт НОВОЕ значение** (апрель: 8 выходных, копий в выходные 5; июль: 8 выходных, копий 6). Это не согласуется с формулировкой «источник в выходные не публикует» (`ADR-049 §3`, основано на `RUNBOOK_v8` журнал 2026-05-13). Факт зафиксирован, **не интерпретирован**.
6. **Май-2026 покрыт 31/31 днём без дыр** — подтверждает `/reference/fx_outbound_coverage_2026-07-26.md §3`, снятое независимым запросом.

## §6 Ограничение метода (обязательная оговорка, `ADR-053 §6`)

Равенство курса двум соседним дням есть **верхняя граница** forward-fill, а не доказательство forward-fill: источник мог легитимно опубликовать одно и то же значение дважды. Поэтому:

- числа `§2`/`§4` читаются как «дней, в которые значение не изменилось», а не как «дней, заполненных механизмом forward-fill»;
- по май-2026 разница между этими двумя чтениями практически отсутствует: одно значение на 31 день при задокументированных в `RUNBOOK_v8` сбоях загрузчика именно в мае (2026-05-13 forward-fill 4 строки; `М-19` 2026-05-18 lag 7 дней → 7 строк; `М-24` 2026-05-21) — совместимо только с длительным forward-fill;
- по апрелю/июню/июлю чтение остаётся верхней границей.

Автоматического вердикта файл не выносит (`ADR-044 §1`): напечатаны строки, трактовка — в `§5`/`§7`.

## §7 Что этот замер НЕ устанавливает — и новый гэп

**Причина малого числа изменений курса не установлена.** Две гипотезы не различены:

- **(A)** дефект загрузчика `cf-fx` / его источника: курс меняется, но в таблицу не доезжает (совместимо с задокументированными сбоями мая и с автоматическим forward-fill при `401`, `PROJECT_REFERENCE_v6` стр.186/757);
- **(B)** официальный курс НБКР действительно малоподвижен, и таблица честно его отражает.

Замер по построению между ними не выбирает — он смотрит только на содержимое таблицы, без независимого источника. Трактовать одну из гипотез как факт запрещено (`_METHOD §6`; `ADR-045 §1` — прямой прецедент отклонения закрытия гэпа догадкой).

**Различитель — дешёвый и read-only:** `cf-fx` пишет GCS-архив ответа источника (`fx-rates/bakai_{YYYY-MM-DD}.json`, `PROJECT_REFERENCE_v6` стр.187). Сравнение значения в архиве со значением в таблице за те же даты различает (A) и (B) без обращения к внешним API. Для до-миграционного периода (май-2026, источник НБКР XLS) архива такого вида может не быть — тогда нужен внешний спот-чек 3–5 майских дат.

**Следствие для решения владельца по `ADR-039 §2`:** ни один из вариантов политики конвертации не исправляет вход, который не меняется. Для мая-2026 варианты «по последнему курсу на конец мая» и «по курсу на дату операции» дают **одно и то же число**, потому что в мае одно значение; различается только вариант «по сегодняшнему курсу». Разбор гипотез (A)/(B) — предусловие содержательного выбора; фиксируется как новый гэп для архитектора.

**Границы контракта замер не задевает:** референс-оракул расходов за май-2026 (`ADR-005`, `/reference/pnl_2026-05.md`; целевая величина 10 232 903,20) выражен в KGS, `total_sum_usd` относится к классу DERIVED (`ADR-039 §2`). Приёмка `E1-T1-MECH` не затронута.
