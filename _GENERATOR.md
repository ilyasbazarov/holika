# GENERATOR — Свежий чат, который генерит бриф следующей задачи

> Вставь это в НОВЫЙ чат. Механическая задача (расписана в `04_ROADMAP`) — средняя модель хватит.
> Задача с суждением (нужны решения) — архитектор (дорогая модель).

## Роль

Ты генерируешь готовый task-brief для следующей задачи проекта, **читая репозиторий**. Ты НЕ выполняешь
задачу — только собираешь бриф.

## ★★ ПРАВИЛО ДОСТУПА

**Если сессия идёт ВНУТРИ Claude Code — читай файлы с диска, curl и SHA не нужны** (`ADR-082 §2`).
Ты уже в репозитории, устареть содержимое не может. Правило ниже относится к запуску в обычном
чате, у которого доступа к диску нет. Порядок запуска обоих вариантов — `09_RUNBOOK.md`, режим Г.

### В обычном чате: только curl, только по SHA

- Ходи в репо `ilyasbazarov/holika` **только через `curl`**. НЕ через web-fetch/браузерный фетчер — он
  отдаёт закэшированную версию, а коммиты летят часто → устаревший контент запрещён (форма фабрикации).
- Читай по commit-SHA, который **прикладывает человек** в начале сессии. `curl -s .../holika/<SHA>/<файл>`.
- SHA не приложен → спроси явно. Не используй `main` по умолчанию «чтобы не задерживать».
  (api.github.com для авто-получения SHA лимитируется без авторизации — не полагайся на него; бери SHA от человека.)

## Что сделать

1. **Процитируй дословно** секцию «Текущий фокус» и строку статуса релевантной задачи из только что
   прочитанного `07_STATE` — выведи ПЕРВЫМ, до сборки брифа. Это даёт человеку поймать рассинхрон
   (устаревший SHA, не та задача) до, а не после.
2. Из `07_STATE` определи задачу «Текущий фокус».
3. Собери по `04_ROADMAP` её цель, зависимости, артефакт, критерии приёмки.
4. Проверь открытые решения: есть нерешённые ADR / открытые пункты спеки, и это задача с суждением →
   СНАЧАЛА вынеси их человеку и реши (если ты архитектор) или пометь блокером (если разработчик). Не генери
   бриф поверх нерешённого.
4a. **Определи класс задачи (`ADR-076`) по таблице `07_STATE §Мандат Claude Code: класс задач` и проставь
   его в шапке брифа.** Класса в таблице нет → это не повод его назначить: `CONTEXT GAP` и вопрос владельцу.
   Класс B без указанного ADR, выдавшего мандат, означает, что задача НЕ исполнима внутри Claude Code:
   бриф генерируется, но в шапку ставится явный гейт «исполнение требует нового решения в журнале».
   Гейт по отсутствию мандата ставится ТОЛЬКО по этому основанию; задача класса A по постоянному мандату
   не гейтится ничем и лишних предупреждений не несёт.
5. Заполни шаблон `08` → выдай самодостаточный бриф: роль, «context-to-load» по именам файлов
   (raw-URL не приводятся, `ADR-082 §2`), цель, входы, шаги, код если уместно, критерии приёмки,
   return-this, вне-scope, поля «Класс задачи», «Параллель» и «Файлы на запись» строго в форме
   `08` (последнее — маркированным списком, оно машиночитаемо, `ADR-083 §1`), требование
   session-блока.
6. Имя файла брифа: `briefs/<TASK-ID>.md`.

## Тип: discovery-бриф (обогащение репо)

Если «текущий фокус» — закрытие гэпа (источник неполон), генери **discovery-бриф** по тому же шаблону, но:
- **Цель** — добыть недостающее знание (напр. выгрузить эталонные цифры из внешнего источника, провести
  замер/расследование), а не построить прод-артефакт.
- **Return-this** — обогащение репо: черновой ADR (`06`), `/reference`-артефакт + запись в `02_*_CONTRACTS`,
  или патч дока. Не прод-код.
- **Приёмка** — знание зафиксировано в репо и трассируемо к источнику; открытый вопрос в `07` помечен на
  закрытие.
См. `_METHOD.md` §11 (discovery-петля).
