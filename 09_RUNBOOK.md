# 09 · RUNBOOK — как запускать сессии

**Версия:** 1.0 · **Статус:** LIVING · **Введён:** `ADR-082`

> Этот документ для ВЛАДЕЛЬЦА, а не для сессии. Он отвечает на один вопрос: что нажать и что
> написать, чтобы запустить работу. Правила самих сессий живут в `CLAUDE.md` и файлах ролей.
>
> Принцип: **ссылки на роли и доки руками не прикладываются.** В Claude Code файл `CLAUDE.md`
> подхватывается сам, остальное сессия читает с диска по нему. Прикладывать ссылки нужно только
> в обычном чате, у которого нет доступа к диску.

---

## 0. Какой режим выбрать

| Что нужно | Режим | Где запускать |
|---|---|---|
| Обсудить архитектуру, принять решение, разобрать проблему, ревью | **Ч** — архитектор | обычный чат либо Claude Code (см. §1) |
| Сделать бриф следующей задачи | **Г** — генератор | Claude Code |
| Выполнить одну готовую задачу | **И** — исполнитель | Claude Code |
| Выполнить несколько задач сразу | **П** — параллель | Claude Code, по дереву на задачу |
| Разобрать накопленные session-блоки | **С** — сборка | Claude Code, основное дерево |

**Правило очерёдности:** если в `reference/_inbox/` что-то лежит либо есть неслитые ветки `s/*`,
сначала идёт режим С, потом всё остальное (`ADR-080 §4v`, `ADR-081 §6`).

Проверка одной командой из корня репо:

```
bash tools/session_status.sh
```

Чисто это последняя строка `ЧИСТО: можно стартовать любую сессию`. Скрипт печатает четыре счётчика,
и читать надо именно числа: голый `ls` каталога буфера показывает одно и то же и когда там лежит
служебный файл `.gitkeep`, и когда каталог пуст, а это разные состояния (`ADR-083 §4`).

---

## 1. Режим Ч — архитектор (обычный чат)

**Когда:** нужно суждение, а не исполнение. Решения, разбор инцидентов, спор о форме, ревью
целостности. Прод-код и облако тут не трогаются.

**Где:** обычный чат. У него нет доступа к вашему диску, поэтому SHA и правило доступа обязательны.

**Что сделать до:** взять актуальный SHA.

```
git rev-parse HEAD
```

**Первое сообщение** (заменить СЮДА_SHA на вывод команды выше, и последний абзац на свой вопрос):

> Актуальный SHA: СЮДА_SHA, читать только через curl по этому SHA.
> Ты — архитектор проекта holika. Роль и правила: `_ARCHITECT.md` в корне репо, плюс `_METHOD.md`
> и `05_CONVENTIONS.md`. Обязательный контекст: `_METHOD`, `00`, `04`, `05_CONVENTIONS`, `06_INDEX`,
> `07_STATE` (состав приведён к `CLAUDE.md §Старт` п.2 решением `ADR-093 §1`; `05_CONVENTIONS`
> обязателен, потому что правило языка ответов живёт операционно только там).
> Репозиторий `ilyasbazarov/holika`, читать по SHA через curl, не через браузерный фетчер.
> Anti-improvisation: гэп есть `CONTEXT GAP` и вопрос мне, не догадка.
>
> Вопрос сессии: ...

**Вариант в Claude Code.** Если удобнее не копировать SHA, тот же режим запускается внутри
инструмента: дерево не заводится (архитектор в репо не пишет), первое сообщение то же самое, но
первые две строки заменяются на «Ты внутри репозитория, файлы читай с диска, curl и SHA не нужны
(`ADR-082 §2`)». Выход одинаков в обоих вариантах: session-блок, который вы кладёте в буфер.

**Куда девается выход** (`ADR-082`): архитектор выдаёт session-блок, вы кладёте его одним новым
файлом в `reference/_inbox/` и коммитите. Применяет его режим С, не вы руками. Правки правил
(`CLAUDE.md`, `05_CONVENTIONS.md`, файлы ролей, этот документ) под буфер не подпадают и идут
отдельным коммитом (`ADR-081 §8`).

## 2. Режим Г — генератор брифа (Claude Code)

**Когда:** задача в очереди есть, брифа под неё нет.

**Где:** Claude Code, ОТДЕЛЬНОЕ рабочее дерево, как и любая другая пишущая сессия (`ADR-083 §6`).
Прежняя запись «основное дерево, дерево заводить не нужно» отменена: сессия пишет два файла в репо
(бриф и файл буфера), а «короткая» свойством безопасности не является.

**Имя — с суффиксом `-GEN`** (`ADR-083 §7`). Так дерево и ветка генерации не сталкиваются с деревом
и веткой исполнения той же задачи, а маска `s/*` при сборке их всё равно находит.

**Что сделать до.** Из корня репо, поправив первую строку:

```
T=SOURCE-MAP-SALES-GEN
git worktree add "worktrees/$T" -b "s/$T" HEAD
echo "открой в приложении: $(pwd)/worktrees/$T"
```

**Первое сообщение** (заменить слово ЗАДАЧА на имя задачи из `07_STATE`, БЕЗ суффикса `-GEN`):

> Ты — генератор брифов. Роль: `_GENERATOR.md` в корне репо, прочитай его первым. Файлы читай
> с диска, curl и SHA не нужны, ты внутри репозитория.
> Задача: ЗАДАЧА. Собери бриф по `08_TASK_BRIEF_TEMPLATE.md` и положи в `briefs/ЗАДАЧА.md`.
> Класс задачи и признак параллелимости возьми из таблицы `07_STATE §Мандат Claude Code`.
> Поле «Файлы на запись» заполни маркированным списком, один путь на строку, в обратных кавычках:
> оно машиночитаемо и по нему проверяется пересечение перед параллельным запуском.
> Ты в отдельном рабочем дереве и коммитишь в свою ветку; session-блок кладёшь файлом
> в `reference/_inbox/`. Гэп есть `CONTEXT GAP` и вопрос мне, не догадка.

**Что получите:** файл `briefs/ЗАДАЧА.md` и session-блок в буфере, оба в ветке `s/ЗАДАЧА-GEN`.
Дальше режим С, потом режим И.

## 3. Режим И — одна задача по брифу (Claude Code)

**Когда:** бриф готов, задача идёт одна.

**Где:** Claude Code, отдельное рабочее дерево. Даже для одной задачи — так порядок один и тот же
и не надо помнить исключения.

**Что сделать до.** Из корня репо, поправив первую строку:

```
T=SOURCE-MAP-SALES
git worktree add "worktrees/$T" -b "s/$T" HEAD
echo "открой в приложении: $(pwd)/worktrees/$T"
```

Дальше открыть в приложении папку, которую напечатала последняя строка, и подтвердить доверие.
Каталог `worktrees/` виден в обычном списке файлов — это и было причиной переезда с прежнего
скрытого пути (`ADR-083 §5`). Если понадобится открыть старое дерево из `.claude/worktrees/`,
в диалоге выбора папки помогает `Cmd+Shift+G` с полным путём либо `Cmd+Shift+.` для показа
скрытых файлов.

**Первое сообщение** (заменить слово ЗАДАЧА):

> Ты — исполнитель. Мандат: ровно один бриф `briefs/ЗАДАЧА.md`, шаги за его пределами не исполняешь.
> Законы: `CLAUDE.md`, стандарты: `05_CONVENTIONS.md` Части I и II.
> Ты работаешь в отдельном рабочем дереве и коммитишь в свою ветку. `07_STATE`, `06_DECISIONS_LOG`
> и `06_INDEX` не правишь, session-блок кладёшь файлом в `reference/_inbox/`.
> Не-идемпотентное — только после моего явного подтверждения. `Done` — только по подтверждённому логу.

**Что сделать после:** режим С. Он сольёт ветку, разберёт буфер и уберёт дерево. Сами дерево не
удаляйте и ветку не сливайте.

## 4. Режим П — несколько задач сразу (Claude Code)

**Когда:** две и более задачи, у каждой в таблице `07_STATE §Мандат Claude Code` в колонке
«Параллель» стоит `да`.

**Условие параллелимости состоит из двух частей, и вторая проверяется машиной, а не памятью**
(`ADR-082 §1`, уточнён `ADR-083 §1`):

1. **Допуск** — колонка «Параллель» = `да`, то есть класс A и полный набор файлов на запись
   объявлен в брифе. Класс B не параллелится никогда. Признак не проставлен = не параллелится.
2. **Непересечение наборов** — это свойство ПАРЫ задач, и одна задача его знать не может.
   Проверяется перед запуском, ОБЯЗАТЕЛЬНО, до первой команды заведения дерева:

```
bash tools/parallel_check.sh SOURCE-MAP-SALES SOURCE-MAP-REST
```

Скрипт печатает наборы обеих задач целиком и все пересечения. `ПАРАЛЛЕЛЬ ЗАПРЕЩЕНА` (код возврата 1)
— запускать по одной. Код возврата 3 означает, что у какой-то задачи поле «Файлы на запись»
отсутствует или записано не списком: это ОТКАЗ проверки, а не разрешение — сначала чините бриф.

**Живой пример:** `SOURCE-MAP-SALES` и `SOURCE-MAP-REST` обе несут `да`, но обе пишут в
`11_INFRA_FACTS.md`. По отдельности каждая параллелима, вместе — нет. Проверка это печатает.

**Что сделать до.** Только после зелёной проверки, по одной строке на задачу:

```
T1=SOURCE-MAP-SALES
T2=SOURCE-MAP-REST
git worktree add "worktrees/$T1" -b "s/$T1" HEAD
git worktree add "worktrees/$T2" -b "s/$T2" HEAD
git worktree list
```

Дальше открыть каждую папку в приложении отдельной сессией. Первое сообщение как в режиме И, своё
на каждую задачу.

**Чего не делать:** не открывать две сессии на одной папке. Это и есть инцидент 2026-07-28
(`ADR-080 §1-§3`), он воспроизводится при любой аккуратности с git-командами.

**Что сделать после:** один режим С на всю пачку, не по одному на задачу.

## 5. Режим С — сборка буфера (Claude Code)

**Когда:** в буфере есть файлы либо есть неслитые ветки `s/*`. Идёт первым и в одиночку.

**Где:** Claude Code, ОСНОВНОЕ дерево, не в `worktrees/`. Это единственное исключение из правила
«любая пишущая сессия идёт в своём дереве» (`ADR-083 §6`), и оно структурное: сборка сливает ветки
в `main`, а из связанного дерева этого не сделать (`ADR-081 §7`).

**Первое сообщение** (копировать как есть, подставлять нечего):

> Ты — проход сборки буфера session-блоков. Роль и правила: `_ASSEMBLER.md` в корне репо, прочитай
> его первым и следуй ему буквально. Обязательный контекст — по `CLAUDE.md`, секция «Старт каждой
> сессии», пункт 2.
> Разбери буфер `reference/_inbox/` и примени по правилам роли. Номера решений присвой сам по
> правилу раздела 5. Всё одним коммитом, поимённо. Пуш не делай, он за владельцем.
> Anti-improvisation: любая неясность, неточная цитата или расхождение с содержимым репо есть
> остановка и вопрос мне, не догадка.

**Чего ждать:** сессия будет спрашивать подтверждение на удаление файлов из буфера и на правки.
Это норма, `git rm` и запись не в списке разрешённых команд, и менять это мы не собираемся.

**После:** `git push` и всё.

## 6. Шпаргалка

| Действие | Команда |
|---|---|
| Проверить, чисто ли | `bash tools/session_status.sh` |
| Проверить пару задач на параллель | `bash tools/parallel_check.sh ЗАДАЧА1 ЗАДАЧА2` |
| Актуальный SHA для чата | `git rev-parse HEAD` |
| Завести дерево | `T=ИМЯ` затем `git worktree add "worktrees/$T" -b "s/$T" HEAD` |
| Завести дерево под генерацию брифа | `T=ИМЯ-GEN` затем `git worktree add "worktrees/$T" -b "s/$T" HEAD` |
| Посмотреть деревья | `git worktree list` |
| Выложить наверх | `git push` |

Деревья и ветки убирает режим С. Руками не удаляйте: `git worktree remove` при несохранённой работе
молча ничего не скажет, а `git branch -D` снесёт неслитую ветку вместе с работой сессии.

## 7. Если что-то пошло не так

**Сессия остановилась и задаёт вопрос.** Это штатное поведение всех ролей. Отвечайте по существу и
не подсказывайте ей нужный ответ: остановка обычно означает реальное расхождение в репо.

**Хук завалил коммит.** Читайте текст, там написана конкретная проверка. Обходить через
`--no-verify` нельзя без отдельного разрешения: сломанная проверка хуже отсутствующей
(`ADR-072 §3`).

**Буфер не пустеет.** Значит сборка не дошла до конца. Не запускайте новые сессии, разберитесь
сначала: непустой буфер даёт протухший `07_STATE`, а это худший отказ этого метода.

**В основном дереве грязный статус во время работы сессии.** Изоляция нарушена. Остановите сессию
и позовите архитектора: это тот самый инцидент, ради которого построен весь этот порядок.

---

## 8. Что в этом документе не проверено

Выбор роли через механизм агентов Claude Code (`.claude/agents/`) описан как ускорение, но на
десктопном приложении не проверен наблюдением. Тексты первого сообщения выше работают без агентов
и являются основным способом. Проверка закрывается первым прогоном (`ADR-082 §3`).
