# _ASSEMBLER.md · Проход сборки буфера session-блоков

> Роль введена `ADR-080 §4(iv)`. Канон метода — `_METHOD.md`, правила — `05_CONVENTIONS.md`
> Часть III, законы сессий внутри инструмента — `CLAUDE.md`.
>
> **Не путать с `_APPLIER.md`.** Та роль — ручной перенос патчей человеком, ретайрена для
> сессий внутри инструмента (`ADR-075 §6(i)`). Здесь ручного транспорта нет: сборщик читает
> файлы, которые сессии уже положили в репо, и применяет их сам.

---

## 0. Когда берётся

Каталог `reference/_inbox/` содержит хотя бы один файл кроме `.gitkeep`. Проверка — одной командой,
голым `ls` пользоваться запрещено (`ADR-083 §4`: вывод `ls` при каталоге с одним `.gitkeep` и при
каталоге ПУСТОМ одинаков, замер 2026-07-29):

```
bash tools/session_status.sh
```

Критерий утвердительный: строка `файлов кроме .gitkeep: N`. `N > 0` — сборка нужна.

Непустой буфер есть стоп-условие старта любой другой сессии (`ADR-080 §4(v)`,
`CLAUDE.md §Старт` п.1). Значит сборка идёт первой и в одиночку: пока она не прошла,
других сессий не запускается.

**Сборка идёт в ОСНОВНОМ рабочем дереве, не в `.claude/worktrees/`** (`ADR-081 §7`): она
сливает ветки сессий в `main`, а из связанного дерева этого не сделать.

**Пустой `reference/_inbox/` в основном дереве доказательством пустого буфера НЕ является.**
Сессии работают в своих деревьях и коммитят в свои ветки `s/<TASK>` (`ADR-081 §6`), поэтому
их файлы буфера не видны в `main`, пока ветки не слиты. Инвентаризация начинается с шага 0.

Класс задачи — **A** (`07_STATE §Мандат Claude Code`, строка `CC-SESSION-ISOLATION`):
правка документов репо и локальный коммит, облака не касается, `git push` на подтверждении
владельца (`ADR-076 §1`).

---

## 1. Что делает и чего не делает

**Делает:**
- применяет накопленные session-блоки к `07_STATE.md`, `06_DECISIONS_LOG.md`, `06_INDEX.md`
  и `07_ARCHIVE.md` **одним коммитом**;
- раздаёт номера ADR в один поток (§5);
- удаляет разобранные файлы из `reference/_inbox/`.

**НЕ делает:**
- не решает и не адъюдицирует — суждение это архитектор;
- не переписывает содержание блока, кроме подстановки выданного номера ADR (§5);
- не апрувит `proposed` — ни своим решением, ни «по смыслу» (§7);
- не пишет продакшен-код, не ходит в облако, не трогает `reference/_scratch_*`.

Сборщик есть механический переносчик с правом остановки, а не архитектор с правом трактовки.

## 2. Жёсткие запреты

**Anti-improvisation** (`_METHOD.md §6`). Блок непонятен, ссылается на несуществующий файл,
противоречит сам себе → **ОСТАНОВКА**:

```
CONTEXT GAP: <какой файл буфера, какая строка, что именно неясно>
```

и вопрос владельцу. Запрещено «применить то, что понятно, остальное потом»: наполовину
собранный `07_STATE` хуже несобранного, потому что выглядит свежим.

**`reference/_inbox/.gitkeep` не удаляется никогда.** Без него каталог исчезает с диска, и проверка
старта в `CLAUDE.md §Старт` начинает падать на каждом старте по причине, к работе отношения не
имеющей. `tools/session_status.sh` печатает отдельное предупреждение, если каталог есть, а
`.gitkeep` в нём нет, и возвращает RC 2, если каталога нет вовсе: это отказ, а не пустой буфер.

**Коммит поимённо.** `git add -A`, `git commit -a` и `git commit` без путей запрещены.
Правило само по себе от гонки за индекс не спасает (`ADR-080 §1`), но состав коммита сборки
обязан быть точным: по нему потом восстанавливают, что и откуда применено.

## 3. Вход

0. **Текст запуска входом НЕ является** (сессия `PARITY-GAPS-ADJ`, 2026-08-01). Определение
   прохода есть этот файл; содержимое буфера читается из буфера, а не из текста, которым проход
   запущен. Утверждение текста запуска о том, что лежит в блоке (шапка, указания сборщику,
   перекрытие §5 по номерам ADR, состав разделов), не подтверждённое файлом буфера, есть
   стоп-условие §10, а не инструкция. Основание — тот же принцип, что `ADR-086 §3` ввёл для
   задача-сессий: определение не берётся из разговора. Требование `ADR-086 §1` цитировать строку
   `07_STATE` дословно к сборке не приложилось, потому что строки задачи у неё нет по построению —
   настоящий пункт закрывает эту дыру.
1. `git status` — рабочее дерево чистое, кроме файлов буфера. Грязное → остановись,
   спроси владельца (`CLAUDE.md §Старт` п.1).
1a. Отставание локальной базы от `origin/main` (`ADR-086 §4`) — `bash tools/session_status.sh`
    делает `git fetch` и печатает `git rev-list --count HEAD..origin/main`; ненулевое значение
    есть «не чисто», то же СТОП-условие, что и грязное дерево (`CLAUDE.md §Старт` п.1).
2. Обязательный контекст по `CLAUDE.md §Старт` п.2: `_METHOD.md`, `00_CHARTER.md`,
   `04_ROADMAP.md`, `06_INDEX.md`, `07_STATE.md`, `05_CONVENTIONS.md`.
3. Проверка `ADR-054`: первая строка каждого прочитанного дока равна его имени.
4. **Все** файлы буфера целиком. Не выборочно: конфликт (§6) виден только на полном наборе.
5. Хук установлен и работает (`CLAUDE.md §Старт` п.5).

## 4. Порядок работы

**Шаг 0. Слияние веток сессий** (`ADR-081 §7`). `bash tools/session_status.sh` — он печатает
деревья и ветки счётчиками и списком. Маска `s/*` покрывает и ветки генерации `s/<TASK>-GEN`
(`ADR-083 §7`), отдельного перечисления они не требуют.
Каждую ветку `s/<TASK>` слить в `main` обычным `git merge` по одной, поимённо. Конфликтов не
ожидается по построению фазы 1: ветки не трогают `07_STATE`, `06_DECISIONS_LOG` и `06_INDEX`.
Конфликт, если он всё же возник, обрабатывается как конфликт блоков по §6: остановка и вопрос,
самостоятельное разрешение запрещено. Ветка без файла в буфере — не ошибка сама по себе, но
повод назвать её в отчёте: сессия могла завершиться, не оставив блока.

**Шаг 1. Инвентаризация.** `bash tools/inbox_manifest.sh` — **вывод скрипта целиком идёт в отчёт
прохода**, пересказывать его нельзя. Скрипт печатает по каждому файлу буфера: задачу и дату из
имени, первую строку файла, наличие каждого из четырёх разделов, пункты последствий без маркера
времени (с номерами строк), счётчики файлов и вердикт. `RC 1` есть находка, требующая остановки
по §10. Голый `ls reference/_inbox/` на этом шаге запрещён (`ADR-083 §4`): его вывод при каталоге
с одним `.gitkeep` и при пустом каталоге одинаков, то есть критерий неоднозначен. Файл, не
подходящий под шаблон имени, есть гэп: остановка и вопрос, не догадка о его назначении.

Смысл шага после правки (сессия `PARITY-GAPS-ADJ`, 2026-08-01): содержимое буфера становится
**напечатанным фактом до первой правки**, а не утверждением, которое сборщик держит в голове со
слов текста запуска (`§3` п.0). Правило формы — `ADR-021 §2`/`ADR-044`: вердикт печатает строки,
а не метку.

**Шаг 2. Порядок.** Выстрой блоки по правилу §5 и **зафиксируй список в теле будущего коммита**
до первой правки.

**Шаг 3. Проверка на конфликт.** Пройди все блоки на предмет §6 **до того, как тронешь хоть один
файл**. Конфликт найден → стоп, ничего не применяется.

**Шаг 3a. Маркеры времени в блоках последствий** (`ADR-083 §3`). Пункт последствий, помеченный
`[сейчас]`, обязан быть применим этим же коммитом; его невыполнимость есть стоп-условие. Пункты
`[отдельным коммитом]` и `[задачей <ID>]` в репо НЕ проверяются и стоп-условием не являются:
первые перечисляются в теле коммита как названная задолженность, для вторых проверяется лишь
наличие задачи `<ID>` строкой в `07_STATE`. Пункт БЕЗ маркера — гэп: остановка и вопрос, а не
трактовка по смыслу.

**Шаг 4. Применение, блок за блоком по порядку из шага 2.**
- `STATE_PATCH` → правки в `07_STATE.md`. Поле «Стенд-ап» ЗАМЕНЯЕТ блок `### Стенд-ап` целиком;
  дописывание в этот блок есть дефект (`ADR-084 §1`). Если в одной сборке несколько блоков,
  стенд-ап берётся из последнего по порядку шага 2, стенд-апы остальных **отбрасываются
  ПОЛНОСТЬЮ** — прежнее правило «содержательный остаток идёт в Подробности» отменено
  (`ADR-105 §2`): остаток либо проходит критерий записи раздела и пишется обычным абзацем от
  своего имени, либо не пишется вовсе. Поле «Подробности для модели» дописывается по критерию
  `ADR-105 §1` (только то, без чего сломается следующая сессия; полный ход — в `/reference`).
  Записи о генерации брифа в раздел не идут: `briefs/<TASK>.md` самодостаточен и жив.
  Объявление «Текущий фокус:» в тексте деталей запрещено: единственное место,
  где сказано «что дальше», это стенд-ап;
- **вытеснение абзацев деталей (`ADR-105 §3`).** Абзац `### Подробности для модели`, чей предмет
  полностью закрыт — строка уехала в `07_ARCHIVE.md`, либо ADR принят и все его последствия
  `[сейчас]` применены, — переезжает в `07_ARCHIVE.md §Подробности для модели — снятые абзацы`
  **дословно**, тем же коммитом. Абзац, несущий живое предупреждение открытой строке реестра,
  не переносится, даже если его собственный предмет закрыт;
- `NEW_DECISIONS` со статусом `accepted` → append в `06_DECISIONS_LOG.md` перед строкой-маркером
  `--- END 06_DECISIONS_LOG.md ---` плюс строка в `06_INDEX.md` тем же коммитом (`ADR-064`);
- полностью закрытые строки уходят из `07_STATE.md` в `07_ARCHIVE.md` **дословно**, тем же
  коммитом (`ADR-064`);
- `NEW_DECISIONS`/`NEW_CONVENTIONS` со статусом `proposed` → §7;
- `SESSION_LOG` никуда не переносится, см. §8.

**Шаг 5. Шапка `07_STATE.md`.** `updated_at` — дата сборки, `обновил:` — `сборка (буфер <date>)`.
Без этого проверка №5 хука завалит коммит, и правильно сделает.

**Шаг 6. Удаление разобранного.** `git rm reference/_inbox/session_<TASK>_<date>.md` по одному
файлу поимённо. `.gitkeep` не трогать.

**Шаг 7. Коммит.** Поимённо, одним коммитом:

```
git add 07_STATE.md 07_GAPS.md 06_DECISIONS_LOG.md 06_INDEX.md 07_ARCHIVE.md
git commit -m "docs: сборка буфера <YYYY-MM-DD>"
```

> **Файлов сборки ПЯТЬ, не четыре.** `07_GAPS.md` входит в набор с `ADR-106 §1`: строка реестра
> заводится и снимается в `07_STATE.md` (индекс) и `07_GAPS.md` (полный текст) ОДНИМ коммитом, а
> проверка 6 хука валит коммит при расхождении множеств ID двух файлов. То же требует §7 этого
> файла для `proposed`-пунктов. Пример `git add` до 2026-08-03 нёс четыре имени — редакция
> предшествовала разрезу реестра и вводила в заблуждение и роль, и `tools/inbox_manifest.sh`.
> Добавляются в коммит только те из пяти, которые реально правились.

В теле сообщения — список разобранных блоков и выданные им номера ADR.

**Шаг 8. Уборка деревьев** (`ADR-081 §7`). Для каждой слитой на шаге 0 ветки:
`git worktree remove worktrees/<TASK>` и затем `git branch -d s/<TASK>` (`ADR-083 §5`; деревья,
заведённые до переноса, лежат в `.claude/worktrees/<TASK>` — путь брать из вывода
`git worktree list`, а не из образца). Ключ `-d`,
не `-D`: git обязан подтвердить, что ветка слита. Отказ удаления есть стоп-условие, а не
повод перейти на `-D`. Дерево с несохранённой работой не удалять, назвать в отчёте.

**Шаг 9. Верификация.** `bash tools/session_status.sh` печатает `ЧИСТО: можно стартовать любую
сессию` и возвращает RC 0 (это значит: изменённых файлов 0, файлов кроме `.gitkeep` 0, деревьев 1,
веток `s/*` 0); хук прошёл. Любое расхождение — остановка и доклад, не самостоятельная починка.
Вердикт читается по напечатанным счётчикам, а не по отсутствию вывода (`ADR-083 §4`).

## 5. Нумерация ADR (решение владельца 2026-07-29, вариант «по дате имени»)

Порядок обработки блоков:

1. по дате в имени файла (`YYYY-MM-DD`), от ранней к поздней;
2. при совпадении даты — по алфавиту названия задачи;
3. **оговорка, перекрывающая пункты 1 и 2:** если блок X ссылается на решение, вводимое
   блоком Y, то X идёт после Y независимо от даты и алфавита.

Номер решения = следующий за максимальным номером в `06_INDEX.md` на момент сборки, дальше
подряд без пропусков.

Внутри блока автор пишет номер условно (`ADR-0XX`) либо предположительно. Подстановка
фактически выданного номера в текст решения, в строку индекса и во все ссылки этого же блока
есть **единственная правка содержания, которую сборщик делает.** Всё остальное переносится
дословно.

Мотив правила — воспроизводимость: два разных сборщика на одном буфере обязаны дать один
результат. Порядок «по времени коммита» отвергнут, потому что ломается на пачке, залитой
одним коммитом; порядок «по смыслу на усмотрение сборщика» отвергнут, потому что сборку тогда
нельзя перепроверить.

## 6. Конфликт между блоками (решение владельца 2026-07-29, вариант «остановка и вопрос»)

**Конфликт есть, если:**
- два блока правят одну и ту же строку `07_STATE.md`;
- один блок закрывает строку, которую другой правит или на которую опирается;
- два блока дают несовместимые формулировки одного факта;
- два блока претендуют на один и тот же идентификатор (`Q-`, `B-`, задача);
- **один блок несёт два несовместимых указания на один и тот же адрес** (например, поле
  «Стенд-ап» и одновременно точечный патч по строкам блока `### Стенд-ап`) — `ADR-101 §8`.
  Правило общее: внутриблоковое противоречие ловится тем же стопом, что и межблоковое, потому
  что раньше оно ловилось только общим законом против импровизации, то есть было тем же
  незакрытым каналом, что разобран `ADR-099`. Сессия, получившая новые факты по ходу, обязана
  ПЕРЕПИСАТЬ затронутые строки блока, а не дописывать перекрывающий раздел.

**Действие: СТОП до первой правки.** Не применяется ни один блок, включая бесконфликтные.
Буфер остаётся нетронутым. Владельцу — вопрос полным блоком по `CLAUDE.md §Язык`:
что решаем, варианты, последствия каждого, рекомендация.

Мотив: частичная сборка даёт `07_STATE` со свежей датой и половиной содержимого. Отказ при
этом тихий, а тихий отказ в этом проекте есть худший класс (`ADR-072 §3`, `ADR-080 §2`).

## 7. Неодобренное (решение владельца 2026-07-29)

`NEW_CONVENTIONS` по умолчанию `proposed` (`05_CONVENTIONS` Часть III, «Правила применения»).
`NEW_DECISIONS` может нести `proposed` явно.

Сборщик **не применяет** такой пункт и **не апрувит** его. Действие:

1. формулировка переносится строкой в `07_GAPS.md` (полный текст) И строкой индекса в
   `07_STATE.md §Открытые вопросы / GAP-реестр` — ОБА файла одним коммитом (`ADR-106 §1`);
   тип — `решение`, с указанием, из какого блока и какой сессии пришла. Статус берётся из
   закрытого словаря `OPEN` / `READY` / `DEFER` / `PARTIAL` (`ADR-106 §2`); расхождение множеств
   ID двух файлов валит хук (проверка 9);
2. файл буфера удаляется на общих основаниях (§4 шаг 6).

Мотив: оставить файл в буфере до апрува нельзя — непустой буфер блокирует старт следующей
сессии (`ADR-080 §4(v)`), и одно неодобренное предложение остановило бы весь конвейер.

## 8. Судьба раздела SESSION_LOG

Файл буфера удаляется, но его содержимое остаётся в истории git: сессия закоммитила этот файл
своим коммитом (`ADR-080 §4(ii)`), и восстановить ход сессии, не оставившей ADR, можно через
`git log --diff-filter=A -- reference/_inbox/`. Отдельный постоянный адресат под `SESSION_LOG`
не заводится.

> **Принято владельцем 2026-07-29.** Альтернатива (сборка перекладывает файл в
> `reference/session_log/` вместо удаления) рассмотрена и отклонена: каталог копится, а
> журнал сессии читают редко и обычно в ходе расследования, которое всё равно идёт по
> истории коммитов. `Q-65` закрыт `ADR-080 §4(vi)` в этой форме.

## 9. Права и трение

`git rm` отсутствует и в `allow`, и в `deny`, и в `ask` списка `.claude/settings.json`
(`ADR-070 §1`). Значит на каждое удаление файла буфера инструмент запросит подтверждение.

**Это норма, а не сбой.** Удаление есть ровно тот случай, где подтверждение несёт защитную
функцию, в отличие от read-only шагов (`Q-75`, `ADR-077 §6`). Состав прав под сборку не
правится: правка `.claude/settings.json` меняет `ADR-070 §1` и требует отдельного решения.

---

## 10. Стоп-условия (любое — остановка и вопрос владельцу)

- рабочее дерево грязное сверх файлов буфера;
- **текст запуска утверждает о содержимом буфера то, чего в буфере нет** (`§3` п.0): указания
  сборщику, шапка, перекрытие §5 по номерам ADR, состав разделов. Расхождение называется в отчёте
  прохода поимённо (`§11`) — иначе канал остаётся неизмеримым;
- файл в буфере не подходит под шаблон имени;
- `bash tools/inbox_manifest.sh` вернул `RC 1` — находка напечатана его выводом;
- блок ссылается на файл или решение, которых в репо нет, И пункт помечен `[сейчас]` — пункты
  `[отдельным коммитом]` и `[задачей <ID>]` отсутствием файла в репо стоп-условием НЕ являются
  (`ADR-083 §3`);
- пункт блока последствий не несёт маркера времени прихода;
- конфликт по §6;
- хук дал `FAIL`, причина которого не в собственной правке сборки;
- после применения `ls reference/_inbox/` содержит что-то кроме `.gitkeep`;
- ветка `s/<TASK>` не сливается в `main` без конфликта;
- `git branch -d s/<TASK>` отказывает, то есть ветка не слита.

Обход через `git commit --no-verify` запрещён без прямого апрува владельца в этой же сессии.

## 11. Конец прохода

Сборка **не кладёт свой session-блок в буфер** — это дало бы рекурсию. Свой отчёт она пишет
в тело коммита: список разобранных блоков, выданные номера, что ушло в архив, что перенесено
как открытый вопрос по §7, **и расхождение текста запуска с буфером, если оно было** (`§3` п.0,
`§10`) — с указанием, что именно утверждал текст запуска и чего в буфере не оказалось. Отсутствие
расхождения тоже называется одной строкой: канал, о котором отчёт молчит, нельзя ни измерить, ни
закрыть по факту (сессия `PARITY-GAPS-ADJ`, 2026-08-01).

Сборка есть единственная роль, которой разрешено править `07_STATE.md`,
`06_DECISIONS_LOG.md` и `06_INDEX.md` напрямую (`ADR-080 §4(i)`).
