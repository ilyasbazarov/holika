## Цель

Установить по КАЖДОЙ таблице датасетов `core` и `marts` проекта `msklad-bi-prod`, **когда она
пополнялась последний раз**, и назвать все, которые пополняться перестали.

Зачем: `core.fact_customer_invoices` найдена замороженной с `2026-06-05` — 58 суток без единой
новой строки, при том что витрина поверх неё пересобирается ежедневно и выглядит живой
(`reference/invoices_staleness_probe_2026-08-02.md`, ветка `s/INVOICES-STALENESS-PROBE`). Находка
случайная — вытянута ниточкой из сверки. Этот прогон отвечает на вопрос, единственная ли она.

## Шаги

Один скрипт на шаг, лог в файл (`bash script.sh > run.log 2>&1`). `date -u` и `gcloud auth list` —
первой И последней командой каждого скрипта (`ADR-055`/`ADR-063`).

1. **Инвентарь таблиц.** `INFORMATION_SCHEMA.TABLES` по датасетам `core` и `marts`: имена, тип
   (таблица/представление), число строк, `creation_time`, `last_modified_time`. Регион явно —
   `asia-east1` (известная ловушка: без `--location` часть метаданных не находится).
2. **Колонка времени загрузки у каждой таблицы.** `INFORMATION_SCHEMA.COLUMNS`: у каких таблиц есть
   `_loaded_at` либо иная колонка времени. Имена НЕ угадывать — печатать найденные.
3. **Возраст данных.** Для каждой таблицы с колонкой времени: `MIN`/`MAX` этой колонки и число
   различных её значений. Различных значений ровно одно = признак единственной массовой загрузки,
   то есть того же класса, что найден на счетах.
4. **Сопоставление с ожиданием.** Для каждой таблицы: кто обязан её пополнять по
   `01_ARCHITECTURE §топология` и с какой частотой; фактический возраст против ожидаемой частоты.
   Расхождение больше двух ожидаемых периодов — в список находок.
5. **Вердикт таблицей:** имя · последнее пополнение · ожидаемая частота · отставание · вердикт
   (`живая` / `отстаёт` / `заморожена` / `колонки времени нет — не проверяема этим методом`).

## Критерии приёмки (Acceptance)

- Покрыты ВСЕ таблицы обоих датасетов; ни одна не пропущена молча. Таблица без колонки времени
  попадает в вердикт отдельной строкой «не проверяема этим методом», а не исчезает из отчёта.
- Вердикт печатает СТРОКИ результатов запросов с числами, а не метку (`ADR-044`).
- Каждая находка «заморожена» подтверждена двумя независимыми признаками (например, единственное
  значение колонки загрузки И отсутствие заданий за наблюдаемый период), либо помечена как
  односторонняя.
- Предел метода назван явно: за какой период видна история заданий и что отсутствие задания в
  этом окне не есть факт «его никогда не было» (`ADR-021 §2`).
