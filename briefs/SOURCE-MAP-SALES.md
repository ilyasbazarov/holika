## Роль

Ты — исполнитель проекта. Законы — `CLAUDE.md`, стандарты — `05_CONVENTIONS.md` Части I и II.
Модель исполнения: ты исполняешь сам (`ADR-082 §2`). Не-идемпотентное — `deploy`, `run`, `update`,
прод-`bq query`, `git push` — только отдельным действием после явного подтверждения владельца, никогда в
связке с диагностикой (`ADR-055 §2`). В этой задаче не-идемпотентных шагов нет по построению: всё, что она
делает в облаке, — `list`, `describe`, `bq show`, `gcloud storage cp` на чтение. Если шаг вдруг требует
записи в облако — это выход за бриф, стоп и вопрос владельцу.
`Done` — только по подтверждённому логу, не по `rc=0` (`05` Часть I ★ Успех инструмента ≠ факт).
Работаешь в СВОЁМ рабочем дереве и коммитишь в СВОЮ ветку (`ADR-081 §6`). `07_STATE`, `06_DECISIONS_LOG`
и `06_INDEX` не правишь: session-блок кладёшь одним новым файлом в `reference/_inbox/`.

**Ты не выводишь карту из данных.** Форма добычи назначена владельцем (`ADR-079 §8`, вариант (a) из трёх):
карта снимается **с живого кода**. Сравнение содержимого `core` с ответами API без чтения кода даёт
гипотезы, а не карту, и воспроизводит ровно тот класс ошибки, против которого стоит `ADR-076 §5.2`.

3. **Секрет не нужен.** Задача не ходит в API МойСклада (`ADR-079 §7a`, основание класса A). Съём имён

### Шаг 1 — найти живой `cf-facts` и снять его метаданные (read-only)

Регион неизвестен ⇒ сначала листинг по всем регионам, потом `describe` по найденному.

```bash
#!/usr/bin/env bash
set -uo pipefail
date -u
gcloud auth list

PROJECT=msklad-bi-prod

echo "=== 1. инвентарь Cloud Functions (все регионы) ==="
gcloud functions list --project="$PROJECT" --format="table(name,state,environment,updateTime)" 2>&1

echo "=== 2. инвентарь Cloud Run (gen2-функции видны и здесь) ==="
gcloud run services list --project="$PROJECT" --format="table(metadata.name,status.url,metadata.namespace)" 2>&1

gcloud auth list
date -u
```

Из выдачи взять **точное имя и регион** функции, обслуживающей продажи. Если функции с именем `cf-facts`
в инвентаре нет — это `CONTEXT GAP`, а не повод выбрать похожую по имени: остановиться и спросить
владельца, приложив листинг.

Затем вторым скриптом (тот же шаг, отдельный запуск после того, как регион известен):

```bash
gcloud functions describe cf-facts --gen2 --region="<РЕГИОН ИЗ ШАГА 1>" \
  --project=msklad-bi-prod --format=yaml 2>&1
```

Зафиксировать дословно: `serviceConfig.revision`, `buildConfig.entryPoint`,
`buildConfig.source.storageSource` (`bucket`, `object`, `generation`), `updateTime`, `state`,
`serviceConfig.serviceAccountEmail`, `serviceConfig.uri`, `serviceConfig.timeoutSeconds`,
`availableMemory`, `environmentVariables`/`secretEnvironmentVariables` (**имена**, не значения),
триггер и его конфигурацию.

Пустая или непарсимая выдача при `rc=0` — гэп наблюдения, не факт (`05` Часть I ★).

константы окна с таблицей `03 §режимы cf-facts` (`hourly` 7, `weekly` 90, `promote` 7/90): совпало —
подтверждение, разошлось — **факт расхождения дока с кодом**, фиксируется как есть, молча не примиряется
(`CLAUDE.md §Граница контракта`).

**(б) Поля ответа → колонки.** Двухзвенная таблица: поле документа МойСклада → колонка
`stg_msklad.fact_sales_staging` → колонка `core.fact_sales_profit`. Обязательно покрыть все сверяемые
величины пары «Инвестор»/«Операционка»: `revenue_kgs`, `cogs_kgs`, `margin_kgs`, а также
`sell_quantity`/`return_quantity`/`sell_sum_kgs`/`return_sum_kgs`, `discount`, `product_id`, `agent_id`,
`entity_type`, `sales_channel_*`, `project_*`. Колонки, у которых источника в документе нет (считаются
у нас — например `cogs_kgs` по FIFO), пометить явно: «расчёт наш, поля-источника в документе нет» —
это ровно тот класс, который `ADR-079 §1` выводит за паритет, но **вывод за паритет этой задачей не
объявляется**, только фиксируется признак.

**(в) Зерно строки.** Подтвердить по коду, что `transaction_id = MD5(demand_id + position_id)`
(`02 §схемы core`) и что зерно = позиция документа, а не документ. Возвраты (`return_quantity`,
`return_sum_kgs`) — из какого документа приходят и как соединяются с продажей.

**(г) Конвертация в KGS (`ADR-010`).** По каждой денежной величине: умножается ли на `rate.value`
документа, делится ли на 100 (минорные единицы), для каких типов документов. Отдельно ответить: есть ли
в sales-ветке тот же дефект, что `ADR-016` нашёл в `cf-finance` (отсутствие `× rate.value` для не-KGS).
**Ответ обязан опираться на печать совпавших строк с номерами** — прецедент ложного греп-вердикта
«валютной починки НЕТ» (`Q-45`, `ADR-044`) относится ровно к этой проверке. Отрицательный результат
однострочного грепа не есть отсутствие конструкции в коде: конструкция бывает разнесена по строкам.
Найденный дефект **не чинится** этой задачей — фиксируется фактом (фикс-форвард отдельной задачей).

**(д) Правило даты — подтвердить или опровергнуть `02 §схемы core`.** Док утверждает: `transaction_date`
DATE, «Дата транзакции в Asia/Bishkek». В staging лежит `transaction_date_raw` STRING формата
`'YYYY-MM-DD HH:MM:SS.mmm'`. Установить по коду: что именно кладётся в `transaction_date_raw` (поле
`moment` документа как отдано API, или уже сконвертированное), и где происходит приведение к DATE —
`DATE(transaction_date_raw)` без указания зоны считает по UTC. Если зона нигде явно не задаётся —
утверждение дока «в Asia/Bishkek» **не подтверждено**, и это фиксируется как расхождение, а не
переписывается в удобную сторону. Кросс-ссылка: `Q-77` (тот же класс на `fact_loss`/
`fact_commissionreportin`, TIMESTAMP→DATE по UTC при локальной зоне UTC+6, внесён в реестр паритета как
кандидат в правило моста).

**(е) Правило `MERGE`.** Ключ сопоставления, режим (`promote`), форма: явный `INSERT (колонки)` или
запрещённый `WHEN NOT MATCHED THEN INSERT ROW` (`05` Часть II C1, `ADR-030`). Форма записи в staging
(`WRITE_TRUNCATE`/`WRITE_APPEND`), идемпотентность повторного прогона, наличие `DELETE`-хвостов.
Триггерит ли `cf-facts` пересборку марта (аналог `cf-finance.trigger_marts()`, `ADR-038`) — важно для
оценки безопасности будущих ручных прогонов, и это факт, а не предположение по аналогии.

## Критерии приёмки (Acceptance)

Проверяемые условия, не «работает»:

1. **Ревизия названа фактом.** `reference/code/cf-facts/MANIFEST.md` несёт конкретную ревизию,
   `source.storageSource` с `generation`, `updateTime`, `state`, `serviceAccountEmail`, `uri` — из вывода
   `describe`, а не из аналогии с другой CF. Регион `cf-facts` получен `list`-командой и совпадает с тем,
   по которому исполнен `describe`.
2. **Снапшот побайтово происходит из задеплоенного архива.** sha256 приведён по каждому файлу; метод
   извлечения (`gcloud storage cp` по пути из `describe`) назван в `MANIFEST.md`. Транскрипция кода
   вручную приёмку не проходит (`ADR-017 §5`).
3. **Карта полей полна по сверяемым величинам пары.** Для `revenue_kgs`, `cogs_kgs`, `margin_kgs` в
   артефакте есть все пять реквизитов `ADR-079 §2`: документ-источник, поле документа, правило конвертации
   в KGS, фильтр периода, зерно строки. Величина, у которой поля-источника нет по построению, помечена
   явно — пустых клеток без пометки быть не должно.
4. **Каждое утверждение о коде трассируется к строке файла снапшота** (`файл:строка` + цитата). Вердикт,
   опирающийся на текстовый поиск, печатает совпавшие строки с номерами (`ADR-044`); голая метка
   `PASS`/`не найдено` приёмку не проходит.
5. **Правило даты закрыто однозначно** — либо «утверждение `02 §схемы core` о `Asia/Bishkek` подтверждено
   строкой <файл:строка>», либо «не подтверждено: зона нигде не задаётся, приведение идёт по UTC» —
   без третьего варианта «вероятно».
6. **Валютный вопрос закрыт однозначно** — есть `× rate.value` в sales-ветке или нет, с печатью строк.
7. **Расхождения кода с `02`/`03` перечислены отдельным разделом** артефакта (файл · § · строка дока ·
   что в коде), без попытки примирить их правкой доков в этой сессии.
8. **Слот `cf-facts` в `11_INFRA_FACTS §CF` больше не пуст**, и его содержимое совпадает с `MANIFEST.md`
   до символа в ревизии и `uri`.
9. **Логи в разделимой форме**, `date -u` и `gcloud auth list` по обоим краям каждого прогона
   (`ADR-055 §3/§4`); деградации авторизации посреди прогона не было. `401`/пустота при `rc=0` —
   гэп наблюдения, перезапуск, а не вывод «данных нет».
10. **Гейт `Q-83` отработан явно:** либо исполнен по содержанию, полученному от владельца (с указанием
    источника), либо в артефакте стоит запись о неисполнении с основанием. Молчание про `Q-83` приёмку
    не проходит.
11. **Границы соблюдены:** численных сверок с МойСкладом не производилось, правило моста не
    формулировалось, `reference/parity_registry.md` не правился, `07_STATE`/`06`/`06_INDEX` не тронуты.

  нарушение мандата, а не экономия сессии.
- **Построчная численная сверка** `revenue_kgs`/`cogs_kgs`/`margin_kgs` с отчётами МойСклада и любой
  вердикт о сходимости. Сверка идёт ПОСЛЕ карты (`ADR-079 §4`).
