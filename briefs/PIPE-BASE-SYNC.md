## Шаги
1. **Пятая проверка в `tools/session_status.sh`.** Добавить секцию, которая:
   - делает `git fetch` (без `--prune`, если не обосновано отдельно — не расширять scope);
   - считает `git rev-list --count HEAD..origin/main`;
   - печатает счётчик положительно (`ADR-044`: «печатать факты, не только метку»), например
     `отставание от origin/main: N`;
   - при `N > 0` — часть общего вердикта «не чисто», RC 1 (тот же контракт, что у остальных четырёх
     фактов).
   Разместить как ПЯТУЮ секцию наравне с существующими четырьмя (`sec "..."` тем же стилем), не смешивая
   с существующими проверками.
2. **Починка счётчика буфера.** Заменить голый `find` на форму, которая исключает git-игнорируемые файлы
   (например: список кандидатов через `find`, затем отфильтровать те, для которых `git check-ignore -q`
   возвращает успех — или эквивалентный по эффекту подход через `git status --porcelain --ignored`;
   выбор конкретной формы — на исполнителе, критерий ниже). Игнорируемый git файл, если он физически
   лежит в `reference/_inbox/`, не входит в счётчик «файлов кроме .gitkeep», но называется отдельной
   строкой-предупреждением (аналогично существующему предупреждению про отсутствующий `.gitkeep`, строка
   26 текущего скрипта), чтобы факт его присутствия не терялся молча.
3. **Прогнать оба локальных сценария до правки `CLAUDE.md`/`_ASSEMBLER.md`:** воспроизвести дефект (создать
   `reference/_inbox/.DS_Store` через `touch`, убедиться что старый счётчик даёт `1`, новый — `0` с
   отдельной строкой-предупреждением; убрать тестовый файл после проверки — он не часть коммита).
4. **`CLAUDE.md §Старт` п.1** — вписать пятую проверку в перечисление фактов той же формулировкой, что и
   в скрипте (не переизобретать текст: «дерево не чище удалённого» / «пятый факт» — взять точную
   формулировку из уже добавленной секции скрипта, чтобы документ и код не разошлись словами при
   одинаковом смысле).
5. **`_ASSEMBLER.md §3`** — добавить тот же пункт в список «Вход» (после существующего пункта 1 про
   `git status`), с явной ссылкой `(ADR-086 §4)`.
6. **Регрессия хука.** `bash tools/hooks/selftest.sh` — ожидание «провалено 0». Это не тест нового кода,
   а проверка, что правка `CLAUDE.md`/`_ASSEMBLER.md` не потревожила то, что матчит хук (например,
   заголовок первой строки файла, `ADR-054`).
7. **Живой прогон.** `bash tools/session_status.sh` в этом рабочем дереве — убедиться, что пятая секция
   печатается и не ломает существующий вердикт (дерево связанное, буфер пуст — ожидается тот же RC 0,
   что и до правки, плюс новая строка счётчика).

## Критерии приёмки (Acceptance)
- Скрипт на отстающей от `origin/main` базе печатает счётчик отставания и возвращает RC 1 (воспроизвести
  локально: смоделировать отставание, например сравнить с заведомо более старым коммитом через временный
  `git fetch` в тестовую ссылку, либо иным способом, не требующим реального `push` — форма проверки на
  исполнителе, важен факт: ненулевой `rev-list --count` даёт RC 1).
- Файл, игнорируемый git (`reference/_inbox/.DS_Store`), физически лежащий в буфере, НЕ входит в счётчик
  «файлов кроме .gitkeep» и называется отдельной строкой-предупреждением.
- `bash tools/hooks/selftest.sh` печатает «провалено 0».
- `CLAUDE.md §Старт` п.1 и `_ASSEMBLER.md §3` называют пятую проверку той же формулировкой, что несёт
  код (проверяется чтением, не автоматически).
- `bash tools/session_status.sh`, прогнанный в этом дереве после правки, отрабатывает без ошибок скрипта
  (валидный bash, RC согласован с существующей логикой связанного/основного дерева).
