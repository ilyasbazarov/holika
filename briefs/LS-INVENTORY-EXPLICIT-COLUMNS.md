## Шаги
1. Снять живую схему таблицы одним read-only запросом, например:
   ```
   bq query --use_legacy_sql=false --format=json \
   'SELECT column_name, ordinal_position FROM `msklad-bi-prod.marts.INFORMATION_SCHEMA.COLUMNS`
    WHERE table_name = "inventory_health" ORDER BY ordinal_position'
   ```
   Пустой/непарсимый вывод при `rc=0` — гэп наблюдения (`ADR-021 §2`), не факт «таблица пуста»:
   перезапросить чисто, при повторе — `CONTEXT GAP`.
2. Построить SQL-текст: `SELECT <явный список колонок из шага 1 через запятую, в порядке
   ordinal_position> FROM \`msklad-bi-prod.marts.inventory_health\`` — конструкция `WHERE date_snapshot
   = (SELECT MAX(date_snapshot) FROM ...)` из текущего снимка сохраняется без изменений.
3. Записать итоговый текст в `reference/sql/msklad_inventory_latest.sql`, сохранив шапку-комментарий
   файла (провенанс снимка, страница дашборда, наблюдение `Q-87`/`ADR-087`) и добавив строку: дата
   съёма живой схемы (локальная дата Бишкека) + одна строка о том, что список — ПОЛНЫЙ (все колонки
   таблицы, не только используемые графиками), по `ADR-087 §7`.
4. Свериться: число колонок в списке должно точно равно числу строк, полученных в шаге 1 (проверяемо
   механически — посчитать и то и другое).

## Критерии приёмки (Acceptance)
- В `reference/sql/msklad_inventory_latest.sql` нет `SELECT *`.
- Число колонок в списке `SELECT` равно числу колонок таблицы `marts.inventory_health` на момент
  правки (снято тем же прогоном, что и список, а не досчитано отдельно).
- Список колонок — ПОЛНЫЙ (все колонки таблицы), не подмножество «используемых графиками» (`ADR-087 §7`).
- Часть запроса `WHERE date_snapshot = (SELECT MAX(date_snapshot) ...)` не изменена.
- Файл остаётся самодостаточным снимком: шапка-комментарий сохраняет провенанс прежнего снимка и
  добавляет провенанс этой правки (дата, источник — живая схема BigQuery).
