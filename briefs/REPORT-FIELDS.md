Известно заранее: `report/profit/bysalesreturn` (report-API вариант) = `404` (уже проверено) — это НЕ то же самое, что `entity/salesreturn` (entity-API), который проверить ещё не пробовали.

## Шаги

1. **Объявление действия класса B** (`ADR-077 §6.ii`, отдельным сообщением ДО ask): назвать, что будет
   исполнено (`gcloud secrets versions access` на секрете `msklad-token`, проект `msklad-bi-prod`),
   что откатывать не нужно (операция read-only). Затем прочитать токен ОДНОЙ командой в переменную
   окружения; `set -x` запрещён; значение нигде не печатается, не попадает в session-блок и в текст
   коммита (`ADR-076 §5.1`).

2. **Различитель `curl` вне списка прав** (`ADR-076 §5.4`): на Шаге 0 вывести `/permissions`, затем
   исполнить один фактический сетевой вызов (например к `report/stock/all`) и зафиксировать в
   session-блоке, как инструмент фактически повёл себя на непере­численной команде (ask/allow/deny).
   Метод вызова — Python `requests` (как в предыдущей сессии `PARITY-REGISTRY`, `run_step2.log`) либо
   `curl`, если он реально проходит без блокировки; в любом случае поведение фиксируется, а не
   предполагается по документации инструмента (`★ Успех инструмента ≠ факт`).

3. **Восемь эндпоинтов, снятие имён полей.** Для каждого — GET с токеном, период `2026-05-01…2026-06-01`
   там, где эндпоинт принимает период (report-API), без периода — где не принимает (entity-API):
   - `report/profit/byproduct`
   - `report/profit/bycounterparty`
   - `report/stock/all`
   - `report/stock/bystore`
   - `entity/purchaseorder`
   - `entity/invoiceout`
   - `entity/salesreturn` (новый, ранее не проверялся; статус может оказаться `404` — это тоже
     результат, фиксируется как факт, не как ошибка сессии)
   - `report/profit/byvariant` (новый, `ADR-085 §7`)

   Для каждого ответа: HTTP-статус, и если тело содержит массив данных (`rows`/аналог) — **ключи
   ПЕРВОГО ЭЛЕМЕНТА этого массива**, построчно, с номером строки лога (`ADR-079 §6`, расширение
   `ADR-044`). Не логировать первые N символов тела — это уже дало неприменимый вердикт в
   предыдущей сессии (`ADR-079 §6 Контекст`).

4. **Различитель зоны `moment`** (`ADR-085 §6`). Взять ОДИН документ, полученный на Шаге 3 (или
   отдельным точечным GET по известному `id`), и сверить значение его поля `moment` с тем, как это
   же время показывает интерфейс МойСклад для того же документа. Инструмент не имеет доступа к
   интерфейсу МойСклад (нет залогиненной сессии, credentials туда не вводятся ни в каком случае) —
   если сверка невозможна без участия владельца (владелец называет документ и что видит в
   интерфейсе), это не гэп, снимаемый чтением репо: задать владельцу ОДИН точечный вопрос полным
   блоком (`ADR-056 §4`) с конкретным `id`/номером документа-кандидата, а не пропускать шаг молча.

5. **Ключи и валюта `report/profit/byvariant`** (`ADR-085 §7`). Помимо имён полей (Шаг 3), явно
   зафиксировать: в каких единицах/валюте выражены денежные поля первого элемента (KGS напрямую,
   или требуется `× rate.value`, или иная база) — по СОДЕРЖИМОМУ ответа (наличие/отсутствие полей
   `rate`/`currency` рядом с суммой), не по семантике «отчётные эндпоинты в базовой валюте» (это
   ровно способ рассуждения, отклонённый `ADR-085 §7` как causa `ADR-016`).

6. **Проверка перед `git add`** (`ADR-076 §5.3`): `grep -rF -- "$MSKLAD_TOKEN" reference/_scratch_REPORT-FIELDS_2026-07-31/ reference/report_fields_2026-07-31.md` — любое совпадение есть стоп, не предупреждение.

7. Собрать `reference/report_fields_2026-07-31.md`: по каждому из восьми эндпоинтов — HTTP-статус,
   имена полей первого элемента (verbatim список), период запроса, ссылка на лог в
   `reference/_scratch_REPORT-FIELDS_2026-07-31/`; отдельные разделы — вывод различителя `moment`
   (Шаг 4) и вывод по валюте `byvariant` (Шаг 5).

## Критерии приёмки (Acceptance)
- Для всех восьми эндпоинтов зафиксирован HTTP-статус; для каждого `200`-ответа с массивом данных —
  verbatim список ключей первого элемента, с номером строки лога-источника (не текстовый пересказ,
  `ADR-044`).
- `entity/salesreturn` и `report/profit/byvariant` получили первую живую проверку статуса в этой
  сессии (были не проверены до неё).
- Различитель зоны `moment` либо разрешён фактом (сверка выполнена, вывод зафиксирован), либо явно
  оформлен как вопрос владельцу полным блоком (`ADR-056 §4`) — не пропущен молча.
- Валюта/база денежных полей `byvariant` зафиксирована по содержимому ответа, не по предположению.
- `grep -rF` по значению токена перед `git add` дал ноль совпадений — зафиксировано в session-блоке.
- Артефакт `reference/report_fields_2026-07-31.md` и каталог `reference/_scratch_REPORT-FIELDS_2026-07-31/` закоммичены.
