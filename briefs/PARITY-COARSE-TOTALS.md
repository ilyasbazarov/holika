## Цель

Получить **грубые итоги** по трём парам реестра паритета, которые не измерялись ни разу: остатки
товаров, заказы поставщикам «в пути», счета покупателям. По каждой паре — три числа: сторона
источника, наша сторона, разность. Причины расхождений НЕ устанавливаются.

Зачем: без этих трёх чисел размер остатка проекта неизвестен, а форма фикса по уже найденным
расхождениям выбирается вслепую (`reference/process_freeze_2026-08-02.md §1`).

## Шаги

Один скрипт на шаг (`ADR-077 §6`), лог в файл (`bash script.sh > run.log 2>&1`). `date -u` и
`gcloud auth list` — первой И последней командой каждого скрипта (`ADR-055`/`ADR-063`).

1. **Зерно пары счетов.** Прочитать `reference/sql/sq_marts_customer_invoices_ar.sql` и вывести,
   является ли `marts.customer_invoices_ar` снимком «на сейчас» или рядом по датам. От ответа
   зависит окно сравнения в шаге 4. Вывод записать в артефакт с цитатой строк SQL. Не угадывать:
   не выводится из SQL → `CONTEXT GAP`.
2. **Наша сторона, все три витрины, одним окном.** Read-only `bq query` по трём витринам:
   итоговая величина каждой (остатки — `stock`-компонент; в пути — `in_transit_sum_kgs`; счета —
   `sum_kgs`, `payed_sum_kgs`, `unpaid_sum_kgs`) плюс число строк. Момент начала и конца окна
   зафиксировать в UTC.
3. **Сторона источника, в том же окне.** Живые `GET`: `report/stock/all`; `entity/purchaseorder`
   с фильтром по статусам «В пути» и «Прибыл частично»; `entity/invoiceout` с разрезом по
   `state.name`. Сырые тела ответов сохранить в `_scratch`. В лог — имена полей строки данных
   (ключи первого элемента массива строк), НЕ первые N символов тела (`ADR-079 §6`).
4. **Три разности.** По каждой паре: число источника, наше число, разность абсолютная и в
   процентах. Для пары счетов окно берётся по результату шага 1.
5. **Запись результата.** Артефакт `reference/parity_coarse_totals_<date>.md` (полный ход,
   команды, окна UTC, сырые числа) и строки 21–23 `reference/parity_registry.md` — колонка
   «Статус сходимости» получает три числа и ссылку на артефакт. Остальной файл не трогать.

## Три ловушки, названные заранее

- **Одновременность.** Остатки и заказы «в пути» — снимочные витрины. Обе стороны снимаются в
  одном окне, окно фиксируется в UTC (`ADR-079 §3`). Иначе разность неатрибутируема.
- **Валюта не конвертируется.** `entity/*` отдаёт суммы в минорных единицах. Если на стороне
  источника есть не-KGS документы — сообщить их **число и сумму отдельной строкой**, к сому не
  приводить. Политика конвертации есть предмет отдельных решений и источник уже случившегося
  дефекта; молча применённое правило превратило бы замер величины в проверку правила.
- **Витрина не пересобирается ради замера.** Сравнивается то, что лежит. Устаревание витрины
  относительно источника — часть результата, а не помеха.

## Критерии приёмки (Acceptance)

- Три пары измерены, по каждой три числа (источник / наше / разность) плюс окно в UTC.
- Сырые тела ответов источника сохранены в `_scratch` и воспроизводят опубликованные числа.
- Токен не напечатан нигде: перед `git add` выполнен `grep -rF -- "$MSKLAD_TOKEN"` по каталогу
  сессии, вывод пуст, факт проверки зафиксирован в логе (`ADR-076 §5` п.3).
- Строки 21–23 `reference/parity_registry.md` несут числа и ссылку на артефакт; diff файла не
  затрагивает ни одной другой строки.
- Ни одна причина расхождения не объявлена. Гипотеза, если возникла, записана как гипотеза с
  пометкой «не проверялась этой сессией».
