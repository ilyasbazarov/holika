## Шаги

2. Восстановить форму ответа `entity/invoiceout`, каким его видит существующий код-снапшот

   упоминания полей счёта (`sum`, `payedSum`, `state`, `agent`, `salesChannel`).
3. Если ни один снапшот кода не содержит парсинга `entity/invoiceout` — это ожидаемо (загрузчика
   счетов как элемента конвейера никогда не строилось, `ADR-110 §0`). В этом случае форма ответа
   API восстанавливается **read-only живым `GET`-запросом** к `api.moysklad.ru/api/remap/1.2/entity/invoiceout`
   с одним документом (`limit=1`) — это чтение, не запись, укладывается в мандат класса A по
   `ADR-091 §1` (действие, не тема, определяет класс); секрет `msklad-token` резолвится inline
   (`ADR-014`). Если секрет недоступен через `gcloud` — `CONTEXT GAP`, не подставлять плейсхолдер.
4. Построить построчное соответствие для каждой из 14 колонок таблицы:
   `invoice_id`, `invoice_name`, `moment`, `agent_id`, `agent_name`, `state_id`, `state_name`,
   `sum_kgs`, `payed_sum_kgs`, `unpaid_sum_kgs`, `payment_planned`, `sales_channel_id`,
   `sales_channel_name`, `_loaded_at` — с указанием поля-источника JSON (путь) для каждой.

   дефектных веток.
6. Вывести правило пересчёта валюты для `sum_kgs`/`payed_sum_kgs`/`unpaid_sum_kgs`: минорные

8. Собрать артефакт `reference/invoices_field_map_<date>.md`: таблица соответствия полей,

- Соответствие полей `entity/invoiceout` → всех 14 колонок `core.fact_customer_invoices` выведено

  повторного чтения кода-снапшота.
