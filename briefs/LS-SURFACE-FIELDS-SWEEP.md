## Цель
Для каждой из трёх ещё не измеренных пар реестра паритета (остатки, заказы поставщикам «в пути»,
счета покупателям) установить: какой именно график(и) Looker Studio выводит сравниваемую величину на
экран, и точный состав его полей (отображаемое имя → колонка марта/`core`-таблицы, где сопоставление
устанавливается). Если ни один график величину не рисует — зафиксировать это явно, тем же способом,
каким это было зафиксировано для пары «Возвраты покупателей» (`ADR-114 §2`). Результат — предусловие
для `PARITY-STOCK-INTRANSIT`: без него слот класса B может быть потрачен на сверку величины, которой
на экране нет.

## Входы
- Три строки реестра паритета (см. выше) с текущим статусом «требуется» либо «грубый итог, причина
  не установлена» — ни у одной нет built-in утверждения о видимости на графике.
- Инвентарь `LS-QUERY-SNAPSHOT` покрывает страницы и источники полностью (пять Custom Query, шесть
  прямых подключений к `marts.*`), но состав полей ГРАФИКОВ снят только частично (одна таблица из
  как минимум трёх релевантных источников).
- Источники, релевантные трём парам, по инвентарю: `msklad_inventory_latest` (остатки, страница
  «Склад», семь графиков на одном источнике), `in_transit` (заказы в пути, страница «Закупки», прямое
  подключение к `marts.in_transit`), `msklad_customer_invoices_ar` (счета покупателям, страница
  «Операционка», прямое подключение к `marts.customer_invoices_ar`).

## Шаги
1. По каждому из трёх источников выше — спросить владельца прямо в этой чат-сессии (форма как у
   `LS-QUERY-SNAPSHOT`): какие графики сидят на источнике, и для каждого — точный список
   отображаемых полей (имя, как оно подписано на дашборде). Не предполагать состав по названию
   графика.
2. Для каждого полученного графика — сопоставить отображаемые поля с колонками таблицы-основы
   (`marts.inventory_health` / `marts.in_transit` / `marts.customer_invoices_ar`), используя живую
   схему (`bq show` read-only или `reference/schema_dump_2026-07-28.md`, если ещё актуален — при
   сомнении в актуальности переснять `bq show`, не полагаться на датированный снимок молча).
   Форма таблицы сопоставления — как в `reference/ls_custom_queries_2026-07-30.md §«Страница
   „Склад“…»` (колонки: отображаемое имя / колонка / статус: «вероятно, единственный кандидат» либо
   «НЕ УСТАНОВЛЕНО, N кандидатов»).
3. Для каждой из трёх пар реестра явно ответить на вопрос: рисует ли хотя бы один график именно ту
   величину, которую параграф `Правило-мост`/`Статус сходимости` строки реестра называет объектом
   сравнения? Да/нет, с указанием конкретного графика или явным «ни один».
4. Если по ходу опроса владельца обнаружится, что какой-то из трёх источников снят не полностью или
   владелец не может ответить сейчас — зафиксировать как `CONTEXT GAP` по этому конкретному пункту
   (не по всей задаче) и продолжить с остальными; не догадываться и не дотягивать недостающее.
5. Собрать всё в `reference/ls_surface_fields_sweep_<date>.md`: по одному разделу на пару реестра,
   в каждом — список графиков, таблица сопоставления полей, явный вывод по Шагу 3, и статус (закрыто
   / частичный `CONTEXT GAP` по названному пункту).
